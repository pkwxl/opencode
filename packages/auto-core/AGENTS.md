# AGENTS.md

Package-level notes for coding agents, kept lean: the index of module → responsibility → key files lives in [docs/structure.md](./docs/structure.md), and the core/shell contract in [docs/shell-contract.md](./docs/shell-contract.md); the CLI shell is the `../auto` package.

## Overview

`@opencode-ai/auto-core` is the core library of the auto tool family (no bin): task pipeline, phase loop, prompt templates, configuration, auto numbering, interruption recovery, unified commit, and other mechanisms are concentrated here and exported via subpaths (`@opencode-ai/auto-core/<module>`) for shell packages to consume. Comments and user-facing messages are written in English, using the terms in [docs/glossary.md](./docs/glossary.md) (Chinese ↔ English).

Distinguish two kinds of knowledge: the task units (`docs/R-NN/P<nn>-<type>/tasks.md`, `docs/T-NNN/`)/`.opencode/auto/config.json`/the `AGENTS.md` block etc. are normative objects the program imposes on the **target directory** at runtime, not file conventions of this repository itself.

## Documentation system (two-tier)

- **Code and comments are the first carrier of design**: structure, invariants, and decision rationale travel with the code.
- `plans/NNNN-<slug>.md` — numbered design/plan document history (ordered by first git commit date): stage-assist documents that only support development during a specific stage, **retired once obsolete and never maintained to track later changes**; originals are preserved untranslated (historical record); new design documents default to English.
- `docs/` — only durable overall architecture, design principles, and code-location indexes (currently shell-contract / structure / glossary); updating them requires good reason. The former `docs/behavior.md` (target-directory runtime behavior contract) was retired verbatim to `plans/0029-behavior-historical.md` (historical record, not maintained).
- This file records only high-frequency invariants + pointers; mechanism details belong to the numbered plans/ documents.

## Commands (run inside this package directory)

- `bun typecheck` — `tsgo --noEmit`.
- `bun test` — runs `test/`.

## Build conventions (developing this program)

- **Templates must keep the `with { type: "file" }` import** — the only way shell packages embed them into the binary at compile time. When adding a built-in template, register it in the same change: prompt templates → the embedded registry in `src/template.ts` (shell-added templates go through `registerTemplate`), mode templates → `src/mode.ts`, intent packs → `src/intent/load.ts`; init copy templates are registered by the shell.
- `src/templates.d.ts` provides path-string types for `*.md` / `*.json` imports; do not remove `resolveJsonModule: false` from `tsconfig.json`.
- Shells reference this package's TS sources and template files directly via `package.json` `exports` (`"./*": "./src/*.ts"`, `"./templates/*"`); new src files need no exports registration. **The core does not know shells** (never import any shell package); shell differences are injected exclusively via the `src/shell.ts` profile or parameter passing.

## Core/shell contract

This package is the core; shell packages (`packages/auto`, the general CLI with bin `opencode-auto`, plus each shell branch's simple shell `packages/<name>` — package name and bin are chosen by each shell and not recorded by the core) depend on this package one-way via subpaths; **shell branches must not modify this package** — differences are injected via `setShellProfile`/`registerTemplate`/parameter passing. The branch model (core changes land only on the auto-core branch, shell branches periodically merge auto-core to refresh the snapshot, auto is the integration branch) and the new-shell onboarding checklist are in [docs/shell-contract.md](./docs/shell-contract.md).

## Core invariants (read before changing)

Developing this program (code-level conventions):

- Task units in the target directory (src/tasks.ts, M3.4): the phase's `tasks.md` is order and membership only (`- [ ] T-NNN <title>`), the unit files win over its ticks (`todo.md`/`done.md`, exactly one); the checklist lives only in `docs/T-NNN/subtasks.md`; runtime state (status, attempts, fork base) is `.auto/units.json`, never a document. A planned `todo.md` carries the title line, a `Phase: R-NN.P<nn>` field and `## Goal`/`## Scope`/`## Acceptance` (spec.ts `taskTodoSpec`). When changing the format, sync `test/tasks.test.ts`, the planning templates and the shell package's README format description.
- Runtime depends on an external `opencode` CLI (spawn `opencode serve`) or `--server` to reuse an existing instance — or, with the claude adapter, on the `claude` CLI on PATH; the binary itself bundles neither.
- **Registry keys and env values are references, never literals** (0055 §4.3, C4): a key is `{env:NAME}` or `{file:path}` and the driver never reads a referenced value into anything it builds — the reference reaches the managed opencode server through the spawn config and is substituted in the server's own process, and a resolved env value goes only into that child's environment. Logs, `models` output and error lines name the reference (`key 2/3 ZHIPU_KEY_B`, `env: HTTPS_PROXY`), never a value. The registry's project layer is local-only: init gitignores it, preflight refuses a layer git would commit (naming `fix`), and nothing but the operator writes either layer.

Designing this program's features (behavior contract imposed on target directories; implementations must not break it):

- Exit codes: `0` complete / `1` usage or environment error / `2` blocked or reverted to pending for human attention / `130` force-quit by two consecutive Ctrl+C.
- Constitutional project attributes (-m/--agent/--context-limit/--subtask/--idle-time/--idle-max/--test-by-driver/--handover-test/--auto-number/--no-auto-number/--wrapup/--no-wrapup/--phases/--parallel/--intent) are fixed into the target directory `.opencode/auto/config.json` by init only (changed per key by `amend`, repaired by rule by `fix`, which never resets a key — plans/0052 D10/D25); appearing at run time is exit code 1; a bad config file fails strictly, unknown keys are ignored; `init` validates everything before its first write (plans/0052 D7) — including the commit-capability prerequisite: inside a git work tree, init refuses (exit 1) when git cannot commit there (`commitIdentityProblem` in `src/git.ts`: no user.name/user.email resolves), because the unified commit is the completion condition; init also writes the wider `.gitignore` set (`ensureInitGitignore` in `src/gitignore.ts`: the driver workdir, the local-only files `/.gitignore`/`/.env`/`/AGENTS.md`/`/opencode.json`/`/.opencode/auto/models.json` (the model registry's project layer, which `reset` never deletes), and every nested git repository in the tree — all removed again by `reset`). The migration source and target are intent, stated in `.opencode/auto/brief.md` (init writes a stub when it is missing; reset removes it only while it equals the stub, D9): `--source-dir/--source-path/--dest-dir` and the config keys `source`/`destDir` were retired on 2026-09-23 (plans/0052 D1–D3) — usage error / strict failure, and both key names are permanent tombstones. A full-overwrite `init` drops a stored retired key and names it with its value instead of failing (D4). **Committing cannot be turned off**: `--commit false` (and the old alias none) and config `commit: false` were retired on 2026-09-15 (plans/0021 D7), and on 2026-09-29 (plans/0061 R13) the flag and the config key went entirely — any `--commit` form is a usage error; a stored `commit: true` loads and is ignored, any other stored value fails strictly with the retired message (`fix` drops it). Committing is the completion condition; the commit side idles only under dryrun and in non-git environments (tests install the no-commit double through the git service seam).
- **driver-exclusive state writes**: the index ticks and the `todo.md` → `done.md` renames are written only by the driver — under parallel lanes the parent re-derives the index ticks at landing (`syncIndexTicks` on a `Auto-Stage: landing-sync` commit, 0068 D6); AI sessions must not edit them; during `run` the config files and AGENTS.md are read-only (src/protect.ts lets the driver's writes through). There is no task mirror: the `CURRENT.md` mirror retired (plans/0054 D3; preflight deletes one an earlier release left), every prompt inlines the task and `docs/T-NNN/todo.md`/`subtasks.md` carry it.
- **AGENTS.md holds only the driver's block** (plans/0054 D1/D2): init/amend/fix/run render it from the config; sessions never maintain the file (it is gitignored, so their edits would escape the unified commit and the unit rollback) and rounds never snapshot it (`AGENTS.md.bak` retired) — durable knowledge goes to committed `docs/` documents. Retired flags and keys (`--verify`, `--review`, `--early`, `--early-review`, `--final-review`, config `verify: true`, the retired session role keys) are usage errors / strict failures (plans/0044 D1/D2).
- **Process documents are not design dependencies (P1)**: nothing a unit adds to the deliverable (any path outside the process roles, minus AGENTS.md and `.opencode/`) may reference `docs/T-*`, `docs/R-*`, `docs/phases/`, PLAN.md or `.auto/` — subtask close-out blocks on it; AUTO-* marker lines may appear in code comments but must be self-contained (plans/0045, root plan D12).
- **Unified commit**: AI sessions must not run commit-type commands; after a session ends the driver commits all changes recursively via src/git.ts (nested sub-repos first, then this repository). **Committing is the completion condition** (plans/0021): unified commit failure → block and halt for human attention; starting an execution unit (task/subtask/standalone hidden task) requires a clean worktree (driver-state leftovers self-heal, other dirty areas block for human; run start follows the same rule); close-out validates via the SHA baseline that the commit range contains only driver commits (Auto-Stage trailer); under parallel lanes the parent's landings add their own stages beside the trailer — `Auto-Stage: landing` (the merge of a lane branch into the main tree), `landing-sync` (the re-derived index ticks) and, on a conflict repair, the lane-side `merge-repair` merge (0068 D7); resumed runs are exempt from the clean check.
- Completion is never judged by agent self-report: subtasks are ticked by the driver from the state files; a unit is done only when its artifacts are on disk and committed (③ commit / ④ dirty, git.ts commitPending/beginUnit), or when a person closed it with `close` — its `Closed:` field records why. Checking work is planned work (acceptance tasks, the v phase); its verdict reaches the driver only as the report result line, and a FAIL stops the run for a person to accept it with `close` or rework it (plans/0044 §3).
- **Experiment switches read the environment only, never persist to disk**: the `OPENCODE_AUTO_*` environment-variable layer (parsed inside the core in src/switches.ts, zero CLI shell changes) writes no state files; experiment semantics = this run only; constitutional keys do not enter ProjectConfig before promotion.
