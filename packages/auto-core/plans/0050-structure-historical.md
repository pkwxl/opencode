- `src/step.ts` — step mode (OPENCODE_AUTO_STEP, design doc plans/0012-step-mode-design.md): three inclusive granularity levels phase<task<subtask (pausing when the boundary order ≤ the gear order, stepApplies being a pure function), hard-pausing at the three boundary kinds — phase handover / task terminal-state commit / subtask tick-and-commit — any input line (including an empty enter) releases, with no timeout auto-continue (unlike --wait-between); stepPause is the pause IO (interactive receives via the resident input line, otherwise readline hard-waits, falling back to auto-release when stdin is closed, io/step injectable for unit tests), the hook points being loop's runTaskLoop/runPhaseLoop (handoverWithStep) and the runner's subtask loop; stepPause wait intervals are deducted from total/AI time and recorded separately as waitMs via statsWaitBegin/End (opts.dir, design doc plans/0019-stats-timing-design.md; with off's zero behavior the statistics are untouched), and all three call sites (loop runTaskLoop/runPhaseLoop and the runner subtask loop) additionally pass dir.
- `src/exit.ts` — graceful `/exit` (design doc plans/0014-exit-resume-design.md): requestExit/exitRequested is a one-shot per-process flag (set by the /exit branch of interactive.ts); maybeExit(boundary, label) reuses step.ts's three boundary hook points (loop's runTaskLoop/runPhaseLoop and the runner's subtask loop, all called immediately after stepPause) — a hit throws ExitRequested, occupying neither of Outcome's blocked/incomplete channels, converted uniformly by loop.ts runAll's top-level catch into exit code 3 (the existing finally cleanup still runs); at that boundary the task's unit files / CURRENT.md / .auto/progress.json have already been properly finalized by the boundary itself, recovery fully reuses resume.ts's existing semantics, introducing no new recovery path.
- `src/failback.ts` — degradation-failback granularity and `/failback` (design doc plans/0017-model-routing-design.md D.6/D.7): failbackApplies is the inclusive-granularity predicate (RANK: phase<task<subtask<session, the same idea as step.ts); three pieces of per-process module state (naturally reset on each CLI invocation, unit tests resetting via resetFailback, the precedent being exit.ts) — sticky (the holder carries the phase gear's cross-task degradation stickiness, written by switchModel, cleared by loop.ts's clearSticky at phase boundaries), pending (a /failback request, set by interactive.ts), override (the runtime model-order override {wildcard, fallback} applied after a parameterized /failback is consumed; attempt's target evaluation and switchModel's candidate loop/trigger gate read it ahead of switches.model, without breaking the switches-memo-stays-constant convention); consumeFailback(chain?) is consumed at the three safe boundaries (the same hooks as step/exit, immediately after maybeExit) — clearing the chain's degradation candidates and sticky, applying the override when parameterized, throwing nothing and occupying no exit-code channel (when both /exit and it are pending, exit wins).
- `src/stuck.ts` — stuck-loop detection (design doc plans/0016-stuck-loop-design.md): the session-scoped detector `createStuckTracker` (pure logic, no SDK types) observes tool-call terminal states and counts on two criteria — error (tool name + error text, **excluding arguments**, 3 times) and repeat (tool name + arguments + output, exactly identical, 4 times), with signature normalization (whitespace folding + lowercase), arguments serialized with keys sorted, long texts hashed into keys, continuity not required (alternating retries are recognized too); a hit returns StuckHit (kind/tool/count/level + argument and result summaries) handed to renderStuckHint to assemble the hint, after which that signature's counter is reset, at most STUCK_MAX_HINTS=3 hints per session, escalating level by level (try a different approach → write a diagnosis first → stop retrying and finish with AUTO-FIXME); **hint-only, never aborting the session**, writing no state files, thresholds and caps being exported constants injectable for unit tests. The hook point is in the runner's watch (the terminal state of tool parts in message.part.updated, deduplicated by part.id with the same discipline as the detail log), controlled by OPENCODE_AUTO_STUCK (default on), and the dryrun preflight session is never checked (being repeatedly rejected is its normal shape).
- `src/stats.ts` — interruption-spanning cumulative statistics (design doc plans/0019-stats-timing-design.md): cumulative time and token breakdowns at the task/session/phase/round levels, persisted to the target directory's `.auto/stats.json` (inside gitignore, driver-exclusive writes, not on the protect list); a single-segment state machine (the open segment folds parallel accumulations into the task/phase/round buckets, clamped to [0, MAX_TICK=30min]) + incremental flushing (a 30s unref heartbeat during sessions, atomic write .tmp→rename + write-queue serialization, write failures fully silent); on load, the depreciation of a segment left by the previous process only admits [open.at, lastWriteAt] (better too little than too much), and a changed round number rolls roundB into history; the public API's first parameter is always `dir: string | undefined` (undefined no-ops): loadStats (returns the resumption snapshot) / flushStats / statsPhase / statsTask (clears sessions) / statsTotals (real-time extrapolation over the open segment) / statsId (guarded read) / statsBoot (this process's start snapshot) / statsHistory (per-round aggregation) / statsSessionBegin/End (the latter returning the printed report) / statsWaitBegin/End (nested-depth counting, overlapping waits counted once); sessions beyond 64 are evicted by at; test hook setStatsClock.
- `src/resolve.ts` — the auto-answer decision ledger (design doc plans/0020-auto-resolve-design.md): it separates the decisions **that should have been asked of the user but were auto-passed or auto-answered by the driver** (AUTO-RESOLVE) from **the engineering discretion the AI was supposed to exercise itself** (AUTO-DECISION), the hard discriminator being "whose call was this decision point supposed to be"; persisted to the target directory's `.auto/resolves.json` (inside gitignore, driver-exclusive writes, not on the protect list, the same family as `.auto/stats.json` but a separate file — stats' 30s heartbeat should not rewrite an ever-growing array of question texts). Two sources: the driver source (question.asked fell back to an auto-answer, runner H1..H3) is authoritative but only covers cases where the session actually asked; the agent source (`AUTO-RESOLVE:` marker lines the session writes into docs/code, collected by the session-close scan H4) covers as much as the session cares to mark; the two are paired via sameIssue (driver items marked matched). The public API's first parameter is always `dir: string | undefined` (undefined no-ops, isomorphic to stats.ts): parseResolveLine (a pure function; separators accept `->`/`→`/`=>`, the reason segment accepts half-width and full-width parentheses, and a line without an arrow becomes the question segment wholesale and is marked malformed but **still counted** — under-reporting an auto-answer costs more than format purism) / recordResolves (append-and-persist, deduplicated by `source + task + 归一化 question` (source + task + normalized question), 512-entry FIFO) / collectAgentResolves (taking uncommitted changed files via git.ts's changedFiles, skipping binary and over-2MB ones, regexing line by line; AUTO-RESOLVE is recorded to the ledger, AUTO-DECISION only increments the per-task counter, and `<…>` placeholders in syntax-explanation lines are not collected) / recordDecisions/decisionsOf (per-task AUTO-DECISION counts, storing only integers without line-level detail, the keys likewise 512-entry FIFO) / resolvesOf (scope ∈ task|phase|round, filtered read-back by bucket identity) / resolveHighlight (a pure function building the `⚑` highlight block: paired driver items yield to the more informative agent item, unpaired ones carry ⚠「会话未按要求标注」 ("session did not annotate as required"), a per-item cap of 8 at task level, phase/round levels giving counts only) / compactText (single-line + 80-char truncation, sharing the same discipline as the runner's in-session immediate line) / sameIssue (hoisted up from runner.ts, serving duplicate-question detection as well as ledger dedup and two-source pairing). Robustness copied from stats.ts: atomic write .tmp→rename + per-dir write queue (what this module serializes is the whole read-modify-write, since each persist must first read back for dedup and matched re-pairing), tolerant per-field parsing, write failures fully silent and never affecting the flow or exit codes; test hook setResolveClock.
- `src/loop.ts` — the runAll shell (**collapsed to 131 lines after the 2026-09-16 S13–S16 split**, plans/0024-module-split-plan.md): `runAll(directory, opts: RunAllOpts)` in turn calls `preflight` (the pre-run checks, see `src/loop-preflight.ts`; error exits return `{ exit }` for runAll to return directly — not through finally, no supplementary cleanup) → manage starts the server (or reuses the opts.managed managed handle) → for `--interactive`, creates the repl one-off bypass input controller → the dryrun permission-preflight session (runOnce, blocked exits 2, completion exits 0) → assembles the `LoopCtx` (directory/path/opts/server/agentName/phases/repl/ran:0) and dispatches by phases: non-phased (`phases === "m"`) first statsPhase("m") then `runTaskLoop(ctx, "m")` (see `src/loop-task.ts`), phased runs `runPhaseLoop(ctx)` (see `src/loop-phase.ts`); the phased flow pre-checks routePhase once before manage (environment errors like an illegal ledger exit 1 early without starting the server; the formal routing is re-evaluated round by round inside the phase loop). The top-level catch converts ExitRequested (thrown at the three step/exit safe boundaries) uniformly into exit code 3 (distinct from 2; rerunning resumes precisely); the finally unhooks SIGINT, closes repl/watcher/progress, flushStats for a graceful close (folding the open segment to disk, write failures silent and not affecting the exit code), closes the server (managed handles belong to the caller and are not closed), and unprotects. SIGINT double-press force-quit: a single press only warns, a second press within the 3-second window closes the server + unprotects then exits 130 (with a 1-second backstop timer). Exit codes: 0 complete / 1 usage or environment error / 2 blocked awaiting a human / 3 /exit safe-boundary pause / 130 double Ctrl+C force-quit. Compatibility re-exports hold up the existing import path `@opencode-ai/auto-core/loop`: `ensureGitignore` (implemented in gitignore.ts), `ensurePointer`/`renderAgentsBlock` (agents-block.ts, imported first then exported locally), `renderAgentContract` and the `RunAllOpts` type (loop-preflight.ts; the migrate shell takes renderAgentContract).
