# 0189 — the wall's close and doors: who closes, what recovers, what reads closed, which order, which remedies

Status: active-authority (0166 remediation step 029, wave W4-wall-perms; findings 0165-008 = S04-01,
0165-037 = S20-01, 0165-038 = S20-02, 0165-076 = S04-07, 0165-149 = S20-12 — all CONFIRMED, the S20
half by the R6-r6/R7-perm leads against this repository's own opencode matcher and tool registry).

The wall family's first two waves (0132's enactment, 0155's failure direction) built the close and its
record; 0188 gave the suites opencode's own matcher as the judge. This ruling owns the seams those
rulings left open, all measured by 0165: two paths cross the sealing handover without the wall (the
0132×0101 meeting), the recovery adopts allows it cannot prove, the closed predicate reads only two of
the channels that re-admit the reference, the seal lands before the person's acceptance, and two of
the wall's own remedy lines teach acts that cannot succeed. One shape connects them: **the wall's
state and its boundaries must be derived from what git and the permission file actually answer, and
every crossing that changes neither must hold loud.**

## The boundary, answered from docs/principles.md first (0123's discipline)

- **P2** — the person brackets every boundary: the wall's close is a consequential boundary 0132
  placed at the person's advance (transfer); a plain run, a `--boundary flow` crossing and a re-entry
  are not the person's advance, so they must neither perform the close nor pass it silently — they
  hold, naming the sealing command. And the person's acceptance gate (the phase's `Gate:`) is a
  person's decision: the seal never consumes it as already given (the gate check precedes the wall).
- **P6** — derived state, re-derivation: the closed predicate re-derives from disk and git; the
  recovery re-derives its targets from git's own record of the door (the last tracked symlink
  content), never from a live allow's shape; an interrupted close is recovered by re-running the same
  derivation, not by a person reproducing driver bytes by hand.
- **P12** — fail loud, conservative under uncertainty: a coverage question the driver cannot prove
  closed reads open; an allow the driver cannot prove its own is a person's entry, never swept into a
  door record; a dangling re-created door counts by what it points at, not by what resolves now.
- **P20** — in-flight work is never destroyed: the hold and the gate stop leave the phase on its
  handover route with the distillation committed; the interrupted close's on-disk retirement is kept
  and finished by the re-run.
- **P8** — every surfaced line teaches its remedy: the hold names transfer; the failed wall commit
  names the re-run that works and the exact record lines a hand commit needs; fix names the reopen it
  refuses to stamp.
- **P7** (grammars, never content), **P10** (the byte-identical floor: no `Wall:` declaration, no
  machinery; undeclared and pre-seal projects byte-identical), **P13** (the record's grammar and the
  protocol lines grow only additively), **P19** (the R7-perm measurements and the 0165 repros are the
  whole ground; the oracle pins the drivers to opencode's own semantics).

## D1 — the seal-due handover holds on every path but the person's advance (0165-008)

0132 D2's trigger reads "the close fires at any transfer whose source phase is at or after the sealing
phase" — but two other paths cross the same handover: `run --boundary flow` (the person asked to flow
across boundaries) and plain run's re-entry of an interrupted transfer handover (0101 D1's recovery
shape). Both closed the phase with the wall open, silently — the next phase's sessions (its
formulation included) ran with the reference readable, and no line said so.

The ruling keeps 0132's placement intact and closes the hole with a hold, not a move: **the close
still runs only under the person's advance path** (stopBefore `formulate` — transfer). Every other
handover path whose phase meets the seal threshold (`wallSealingPhase` defined, no wall record) —
flow, the plain-run re-entry, plan's crossings — **holds before the phase close**: one blocking line
naming transfer as the command that seals, exit 2, the phase stays on its handover route, nothing
renamed, the distillation (already done or done by this crossing) kept and committed — transfer's
re-entry skips straight to the wall. The rejected alternative — closing the wall on every handover
path — is recorded: it would consume the person's boundary inside a plain run (a P2 violation 0132
was written to avoid) and move the admission scan and the seal under commands that never owned them.

Two companion teachings: (a) the re-entry's boundary stop, when the re-entry did complete a handover
(no wall hold — a pre-seal phase, an undeclared project, a post-wall phase), prints a **phase-closed
variant** derived from disk (the phase's done state): "the handover was distilled and the phase
committed … transfer constructs the next phase's plan task", instead of the stale "it distills the
handover, closes the phase" — the same derivation serves the person-proxy brief, which renders these
lines. (b) transfer's own start pre-check stays post-wall only, by design: with the hold in place the
only reachable seal-due state routes at the sealing phase's handover, where transfer itself performs
the close; the legacy overdue shapes (a phase closed past its seal before this ruling) are owned by
0132's retrofit trigger at the next transfer-held handover, and by the hold everywhere else.

## D2 — the recovery adopts only provable door targets (0165-037)

0155 D2's recovery sweeps every live `<path>/**` allow whose base exists on disk and no current door
resolves to: under the 0147 template (which ships `/tmp/**: allow`) that adopts **/tmp** as the
reference target and blocks with "move the reference out of /tmp" — a false target and a remedy that,
followed, disables the receipts convention; without the boundary it flips **any person-authored
existing-path allow** to a deny and records it as `Wall-door:` — the person's words consumed, the
record lying.

The recovery is re-grounded on proof: **a target is recoverable only where git names the door that
admitted it.** For each missing declared door (and, in the no-fill shape, for each top-level name git
ever recorded as a symlink — the summary scan of every add/modify), the door's **last add/modify
commit** holds the final tracked symlink content (HEAD's tree first, for the person's uncommitted
removal); its text — absolute or relative, resolved against the project root and realpath'd — is the
proven target. The live stamp slot `<target>/**` then classifies the state:

- `allow` — the driver's stamp still standing (the hand-removed door, the pre-0189 interrupted
  close): recover, the close retires it (0132 D2's "finish the retirement", 0155 D2's scope, kept);
- `deny` — the retirement already ran and no record landed (the failed wall commit, D5): recover for
  the record alone — the close re-runs idempotently and lands the (possibly empty) record commit;
- absent — nothing to recover (0155's by-design residual: the seal complete by absence), and a
  never-tracked door blocks as before, teaching the re-creation.

An allow the driver cannot prove is **never touched and never recorded as a door**: it stays a person
entry, and where it covers a target being sealed the person-entry split blocks naming it, exactly as
before. The boundary's own keys are structurally excluded — no proof can name `/tmp` unless a tracked
door truly pointed there, and then the close's unsealable check is the correct refusal. Recovered
entries now carry the **proven door name** (git names it), which also lets the closed predicate's
door half watch re-creates of recovered doors; the `(removed)` placeholder survives only as the
reader of records older than this ruling (P13: no grammar change, no silent dual meaning — new
records simply stop writing it, the parser keeps skipping it).

## D3 — the closed predicate reads every channel: the doors re-derived, the coverage evaluated (0165-038)

0132 D2's predicate — "closed iff the door is absent and no live entry covers the recorded target" —
was enacted reading exactly two channels: the recorded door **name** at the top level, and `<path>/**`
**allow** keys whose base lexically covers the target. 0165 measured the rest: a door re-created
under another name or path (a session's `ln -s`, swept into a tracked commit), a subtree allow fix
stamps past the seal, wildcard and `~`-expanded allows, person `ask` keys — each re-admits the
reference while every boundary prints "sealed reference wall closed".

**The door half**: the predicate no longer reads names — it reads **reachability**. Every symlink in
the tree — tracked at any depth (`git ls-files -s`, mode 120000: the deliverable's own set, P1) plus
every top-level entry on disk (tracked or not) — whose resolution (realpath, or, dangling, the link
text resolved lexically — D5's concern) lies **under or over** a recorded target is a reopen finding
naming the path, its resolution and its relation to the recorded target. A top-level re-create at a
recorded door name keeps the "present again" line (the finding's established bytes). Deeper untracked
symlinks stay the clean gates' and the admission scan's (they are dirt at every unit start) — a named
residual, not new walking machinery.

**The allow half**: coverage is no longer a lexical prefix scan — it is **evaluated with opencode's
own semantics**, through 0188's matcher mirror in its one home (`src/external-dirs.ts`, oracle-pinned):
the live `external_directory` section in file key order, `~`/`$HOME` expanded, last-match-wins over
the asks the read tool sends. The ask set is derived, not fixed: `<target>/*` (every catch-all and
ancestor key matches it) plus each live key's **scope ask** (the key minus its trailing wildcards,
`*`-capped) wherever it names a path beneath the target — this is what carries the segment-specific
keys (`<target>/sub/**`) no flat probe reaches. **Any answer other than deny reads open**, and the
winning key is named: the exact stamp slot is the driver's own (finish the retirement — 0155's
"coveringAllowKeys counts only allow" residual closes with it: an `ask` at the slot is re-denied per
0155 D3); any other winning key is a person entry (remove it); **no matching key at all** means even
the wall's deny is gone — its own finding. `coveringAllowKeys`/`coveringEntries` retire with the
scan they enabled (P5); `allowCovers` stays for the boundary's unsealable check.

**The fix half**: `fix`'s root-symlink sync never again stamps the allow half for a real path under
**or over** a recorded wall target (the recorded targets passed in as a parameter — external-dirs
stays wall-agnostic, P14's injection discipline; init needs nothing, a fresh project has no record).
The skipped door is a manual finding naming the reopen — fix teaches the wall's finding instead of
silently desyncing its own report from its apply. The edit-layer denies keep stamping for every door
(harmless defense-in-depth, 0188's residual).

## D4 — the gates read-only before the wall (0165-076)

The handover tail's order was wall → completePhase's gate re-check: on a sealing phase that also
carries a gate, a hold left the wall committed, the door removed and the channel frozen **before**
the person's acceptance — the rework a rejection asks for then collided with the sealed-channel
invariant (and the tracked `opencode.json` retirement sat as dirt at the next start gate, S20-10's
note). The order nobody had ruled as a whole is now ruled: **distillation → regression hold → gates
(read-only) → wall → completion rename → brief install → transition**. A read-only
`phaseGateProblems` ahead of the wall holds the phase (or appends the repair round, through
completePhase's unchanged block — the re-check stays the single choke point, 0049 G7) with nothing
sealed; a passing pre-check lets the wall run, and completePhase's own re-check keeps its place. The
post-wall boundary checks (reopens, the sealed channel, the admission class) run in the wall block as
before — when a gate holds they wait for the gate, and transfer's start pre-check already surfaces
reopens ahead of any session.

## D5 — the edges' remedies made true (0165-149)

- `recreatedDoors` counted an entry by `stat`, which **follows** the link: a door re-created toward a
  corpus mounted later (another machine, a lazy mount) read closed until the target appeared. The
  door half of D3 subsumes the fix: the entry counts by **what it points at** — the dangling link's
  text, resolved lexically, names the recorded tree and reads open now, not when the mount arrives.
- The failed wall commit's line taught "commit the state by hand and re-run (the closed predicate
  reads the record from the commit)" — but a hand commit carries no `Auto-Stage: wall` record, and
  the re-run met a doorless, stamp-retired tree and blocked "no reference door is present". With D2's
  stamp-slot-`deny` recognition the re-run **is** the remedy: the close re-derives the interrupted
  state and lands the record commit itself. The failure line now teaches the re-run first, and — for
  a person who prefers the hand — prints the exact record lines the commit must carry (the
  `Auto-Stage: wall` line and the `Wall-door:`/`Wall-sealed:` lines) so a hand-made record commit is
  readable by the predicate. A person commit made to that recipe is the driver's recovery deputy for
  exactly this act — it is the wall's record, not a person's content.

## The floors

- No `Wall:` declaration anywhere: no wall machinery reads git for the wall, no hold, no finding —
  byte-identical (0132's floor, restated and kept).
- Pre-seal phases (`wallSealingPhase` undefined): the hold does not fire; handovers flow as before.
- A closed wall over plain shapes: the evaluator's verdicts coincide with the retired lexical scan's
  (stamp allow → open-and-finish; deny → closed; person parent allow → open-and-named); the
  person-entry split's behavior over allows is unchanged, its message word generalized to "entry".
- The undeclared, no-fill and never-present blocks keep their lines (the never-present block's
  "no driver-stamped … allow records a target" now means *provable* — the line's substance stands).
- `fix` on a wall-less project: no recorded targets, no skip, no finding — byte-identical.

premises this ruling changes: **0132** (D2's close placement — unchanged in the close itself, but the

## Residuals

- **Agent-level permission sections** (opencode merges an agent's own rules after the top level):
  the evaluator reads the top-level `external_directory` section only — an allow declared on the
  agent's section beneath a sealed target still reads closed to the driver. No measured incident;
  the oracle can be extended to the agent merge when one lands (the reopen trigger, P21).
- **Interior-wildcard ancestor keys at depth** (`/w*k/linux/a/**`-shaped): a key whose scope ask is
  not lexically beneath the target and which does not match the `<target>/*` probe escapes both ask
  sources. Absurd hand-crafted shapes; the measured forms (catch-alls, ancestors, `~`, subtree
  stamps, `ask`) are all covered.
- **Deeper untracked symlinks** (below the top level, never committed): invisible to the tracked
  scan; they are dirt at every unit start (the clean gates) and reach the tracked set through any
  commit — the admission scan's class once committed.
- **The lane-worktree relative depth and the src-side matcher mirror** — 0188's residuals, standing.
- A person who *wants* a persistent post-wall symlink (a convenience link over the corpus) has no
  recorded-reopen register: the finding teaches removal, 0132's standing design; a register is new
  machinery with no consumer (P21).
