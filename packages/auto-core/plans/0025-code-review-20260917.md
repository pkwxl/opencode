# auto-core Full-Repository Code Review Report (2026-09-17)

Scope: all 53 files under `packages/auto-core/src` (about 14,000 lines, auto-core branch).
Method: 6 parallel deep-review groups (main loop / git / session recovery / plan validation / configuration switches / infrastructure) + manual item-by-item re-verification of high-risk findings (✓ marks findings whose source was verified first-hand).

Overall assessment: high engineering quality -- atomic writes, lenient parsing, idempotent state-machine recovery, and dense cross-linking between comments and design documents are all first-rate. Residual risk concentrates in three systematic tendencies: **text-protocol parsing that is too lax, process/timeout boundaries, and git command failures being swallowed into a "clean" verdict**.

---

## High (recommend fixing soon)

### H1. verify timeout only kills the outer bash; the script under test is orphaned and keeps writing the workspace ✓ (two independent findings)

`verify.ts:94-105` + `testrun.ts:266`. Non-executable scripts go through `bash -c 'bash "$0" …'`, and `proc.kill()` kills only the outer layer; the inner script is orphaned and keeps running, rewriting the workspace/output files -- and this is precisely the main path for handover finalization scripts (`tmp/test.<n>.sh` materialized by `Bun.write` is always 0644). Consequence: a test already judged 124 keeps running, colliding with the next unit's clean gate or polluting verdict inputs; the next verify round also truncates the same output file the orphan is still writing.

Fix: a separate process group + kill the negative pid; or change the `bash "$0"` branch to `exec bash "$0"`; or add chmod +x for override scripts.

### H2. `parseVerdict` takes the first match over the full text and is unanchored, allowing false passes ✓

`review.ts:384-392`: `/结论[:：]\s*(通过|差距[^\n]*|重验[^\n]*)/` takes the **first** match anywhere in the full text, and `通过` is moreover a prefix match (a line like "结论: 通过标准是…" -- "Conclusion: the pass criteria are…" -- also hits). If the review session body quotes the verdict criteria first and writes the real "结论: 差距 …" ("Conclusion: gap …") only on the last line, it is judged pass and goes straight to `markDone` (review.ts:150). Compare `parseConclusion` at `final.ts:69`: reverse scan for the last line + line-start anchoring + whole-value equality -- two conventions in one family, and the review side is the oversight. **The only defect that can directly overturn the correctness of completion verdicts.**

Fix: align with final.ts (reverse scanning, `^结论[:：]` line-start anchoring, pass must be whole-line equal); a `差距` (gap) with an empty description is treated as a parse failure.

### H3. `handoffStatus` has the same missing anchoring; a half-finished handover can be misjudged as closed ✓

`handover.ts:99`: `/状态[:：]\s*(继续|完成)/` matches anywhere in the full text; the prompt itself contains the "状态: 继续" (status: continue) instruction, so the AI merely restating it triggers a hit. The handover verdicts at execute.ts:57/124/363/454 and runner.ts:186 and the strict-recovery write check all go through this function -- a half-finished document gets misjudged as "a fully written handover", bypassing the write check and resuming on an incomplete handover, or even checking off subtasks directly.

Fix: anchor at line start (`/^\s*状态[:：]\s*(继续|完成)\s*$/m`) or judge by the last non-empty line.

### H4. Error-classifier substring regexes hit innocent text + `isRetryable===false` is lumped into quota wholesale ✓ (two independent findings)

`chain.ts:180,183,200`:

- `QUOTA_RE`'s `credit` hits "credentials" and `balance` hits "load balancer" (verified by live testing) -- auth/gateway errors get misclassified as quota, and quota sits **before** the retry ladder at session.ts:329 and switches to the fallback model directly, so transient jitter that could have self-healed burns a fallback candidate;
- `TRANSIENT_RE`'s bare numbers `500|502|503|504` hit arbitrary messages like "15000 rows" (milder consequence: it pollutes the classification report);
- `isRetryable === false` is always classified as quota -- deterministic 4xx (e.g. a 400 constructed by the driver itself, SDK parameter errors) burns through the fallback candidates one by one and then enters awaitRecovery infinite waiting, hanging forever instead of surfacing.

Fix: word boundaries / context restriction (`\bcredit\b` with credentials excluded; `insufficient balance` and the like); change the numbers to `\b(500|502|503|504)\b` or match the statusCode field; `isRetryable===false` must be combined with quota evidence (402 or quota wording) before being classified as quota, otherwise list it separately as nonRetryable and skip the fallback ring.

### H5. When nested in a subdirectory of a larger repository, .gitignore is never written; `.auto/` gets committed and self-locks the clean gate ✓

`gitignore.ts:24`: the criterion is "no .gitignore and no .git in this directory means no-op", but `git.ts`'s repoRoots/commitTree explicitly support the larger-repo subtree case (`.git` one level up, and this directory usually has no .gitignore). Consequence: `commitTree`'s `git add -A -- .` commits `.auto/` (stats.json, progress.json, handover.json) and `tmp/` into the user's parent repository; and the stats heartbeat (30s) keeps rewriting the tracked stats.json → every unit's beginUnit is blocked by the dirty state it created itself.

Fix: change the criterion to `git rev-parse --is-inside-work-tree` (same convention as repoRoots), and write .gitignore whenever inside a work tree.

### H6. log.ts crashes calling `prompt()` on a closed readline ✓

> **Erratum (verified empirically during the 2026-09-17 fix)**: the claim "`rl.prompt(true)` throws `ERR_USE_AFTER_CLOSE`" does not hold under either Node 20 or Bun (after close, prompt/pause/resume/write all throw nothing; only the promises `question()` throws, and log.ts does not use it). The real defect is downgraded to asymmetric cleanup: `close()` cleared log.ts's input-line reference while the stdin `close` event did not, so logging kept redrawing the prompt on a closed readline. See the fix record at the end of this document.

`log.ts:53-60` + `interactive.ts:107-111`: when stdin closes (pipe exhausted / Ctrl+D / terminal disconnected), `rl.on("close")` only sets the internal `dead` flag and does not `setInput(undefined)`; log.ts's module-level `rl` reference stays alive, and any subsequent log line triggers `rl.prompt(true)` throwing `ERR_USE_AFTER_CLOSE`, which can punch through the main flow (interactive.ts's settle has a dead guard; the log.ts side lacks the symmetric cleanup).

Fix: also `setInput(undefined)` on close, or wrap log.ts's prompt in try/catch.

### H7. The half-open probe cannot rescue a hung synchronous POST (design doc §4.4 already records this as a trade-off, but the benefit is discounted)

`watch.ts:563-576` + `attempt.ts:216-234` + `server.ts:33`: after the probe declares half-open at ~2×idleTime, what gets aborted is the SSE channel; the blocked `client.session.prompt` (v2 synchronous POST) goes over another connection that is already half-open, the watch error result has no consumer, and the retry ladder only starts after TURN_TIMEOUT (2h) -- longer than the T-068 incident scene (44 minutes). The probe's actual remaining benefit is only releasing the SSE connection quota early.

Fix: race the prompt promise against watching (cancel the POST as soon as watching returns first with an error), or attach an AbortSignal to the POST and abort it together with the half-open verdict.

## Medium

### M1. git command failures swallowed into "clean / no foreign commits" ✓ (tendency confirmed)

`git.ts:214-220` (foreignCommits does not check the `git log` exit code: stale baseline SHA / corrupted repository → returns 0 foreign commits, and unitViolations/baselineIntact/rollbackUnit are all misjudged), `git.ts:163-164` (in unitViolations, a rev-parse failure with `head===undefined` simply continues, inconsistent with baselineIntact:234-238's convention of reporting the problem), `git.ts:442-460` (hasChanges/statusEntries return false/[] on non-zero exit → commitTree skips committing and beginUnit judges clean). This is contrary to the commit-boundary design intent of "rather block than wrongly let through".

Fix: distinguish "command failed" from "empty result"; always handle failures in the conservative direction of dirty / foreign commits present.

### M2. The interrupt-recovery back-fill's commitTree does not check the return value ✓

`loop-phase.ts:402-407`: on the handover interrupt-recovery path (archive already present but the ledger is missing a line), `await commitTree(...)` does not check settled.ok, inconsistent with the same-shaped call at handoverPhase:288-298 (failure exits 2). If this phase is the last one, the next round's routing goes straight to complete → **exit code 0 reports "all done" while the archive/ledger changes are uncommitted**, violating "committing is the completion condition".

Fix: add the same settled.ok check; on failure print the list and return 2.

### M3. The H2/H3 handover-recovery branches do not sync the handovers counter back; a number collision overwrites the archive

`exec-session.ts:135-146` (compare 73, 205-221): closedHandovers returns `record.n - 1` for an unclosed record; the H2-!hasArchived branch correctly does `handovers++`, but the H2-hasArchived branch and the H3 branch only back-fill the record, leaving handovers at n-1. The next handover in the same run reuses number n, and `archiveHandoff`'s rename overwrites the already-recorded testhandoff-<n>.md, violating the invariant "archiving continues numbering from the maximum of both sides and never overwrites".

Fix: after both branches determine closedN, add `handovers = Math.max(handovers, closedN)`.

### M4. Rollback always fails on a repository with no commits; recovery deadloops

`git.ts:288-304`: on a repository with no commits, `git stash push` exits 1 (verified by live testing); a fresh nested repository `git init`-ed by the AI during the run, as long as it has any uncommitted changes, makes rollbackUnit's step ① always fail → dirty goes to a human → deadloop. Also, after the `!sha && head` branch skips reset, the log still claims "redo from the clean baseline", but this unit's driver commits all remain in history.

Fix: for repositories with no commits, switch to "move into a temporary directory / back up before git clean"; for empty-baseline repositories that already have commits, report honestly that fidelity cannot be guaranteed.

### M5. External server health check has no timeout

`server.ts:132-138`: defaultConnect uses a bare `fetch(/api/health)` with no timeoutFetch/AbortSignal; if the target address is half-open / a black hole, manage() hangs forever during the startup phase (at that point neither the probe nor TURN_TIMEOUT is in place).

Fix: add `AbortSignal.timeout(REQUEST_TIMEOUT_MS)` to the health check.

### M6. runSession's catch-all sends the driver's own programming errors into the infinite recovery loop

`session.ts:311-321` (together with 253-256): any exception thrown by attempt (including deterministic bugs like TypeError) is wrapped as "会话错误:" ("session error:") into the retry ladder and awaitRecovery; the probe session goes through the same code path and throws the same way → always judged unrecovered → infinite waiting, burning one probe session for nothing every 30 minutes while the real fault stays masked.

Fix: wrap only known SDK/network error shapes; re-throw all other exceptions unchanged.

### M7. The wrapup shape-check gate cannot distinguish "this run's artifact" from a pre-existing report.md

`wrapup.ts:23-28,48-76`: reportProblems only does existence + shape checks, with no pre-session snapshot / mtime comparison. In fix-round wrap-ups and task-rollback reruns, the old report.md is already committed on record, and the current wrap-up session passes the check despite zero writes to disk -- exactly the "natural end with zero disk writes" shape that session-boundary-hardening is meant to block (understand/decompose have a "skip if already present" pre-path; wrapup does not).

Fix: record (or delete) the old report.md before the session, and have the gate require that the file was rewritten during this session (any one of mtime / hash / baseline diff).

### M8. PROTOCOL_MARKERS does not cover the three execution templates; the testhandoff exclusion clause can be silently removed by an override

`template.ts:98-119`: the exclusion clause "不得自行创建 testhandoff-<n>.md" ("must not create testhandoff-<n>.md on your own") that §L (the 2026-09-17 anti-forgery revision) added to the subtask/fix/whole templates is not in PROTOCOL_MARKERS, so when the target directory's `.opencode/auto/prompts/subtask.md` overrides it and drops the clause, there is no load-time validation at all.

Fix: register markers for the three templates (note the clause sits inside `{{#if handoverTest}}`; the validation must tolerate the not-enabled case).

### M9. The parser silently swallows near-miss task headings

`plan.ts:42,56-60`: lines that do not match HEADING are simply skipped -- wrong status casing (`[Done]`), status typos, missing colons and the like all silently drop the task, and next() skips straight over it without any warning; inconsistent with the strict convention of throwing on duplicate id (plan.ts:62).

Fix: throw a parse error for lines that match `/^## T-[\w-]+/` but do not match HEADING.

### M10. appendTask does not guard against `## ` lines in the body; ghost tasks can be injected

`plan.ts:295-302`: the final-review proposal body (AI-produced) is written into PLAN.md as-is; a body containing lines like `## 背景` (a "## Background" heading) truncates that task's body, and one that happens to contain a HEADING-shaped line (e.g. `## T-F9: … [pending]`) injects a ghost task that the main loop will really execute.

Fix: appendTask rejects or escapes lines in the body that start with `## `.

### M11. agents-block whole-file blank-line folding damages user content

`agents-block.ts:72`: the `\n{3,} → \n\n` folding unconditionally applies to the entire AGENTS.md before deciding whether the block changed (including consecutive blank lines deliberately kept inside code blocks); removePointer's (114, 119) `.trim()` likewise strips leading/trailing whitespace.

Fix: apply folding only to the local seam left after removing the legacy block, or do no whole-file normalization.

### M12. refcheck's fence toggle does not distinguish ``` from ~~~

`refcheck.ts:31`: a fence line of either kind toggles the same fenced state; a ``` block containing a ~~~ example (common in markdown tutorials) misaligns the state, and `path.ts:12` inside a code block gets mis-scanned as a reference → false positive into invalid-refs.md → verify blocks it into a fix round.

Fix: record the opening fence's character type and close only on the same type (CommonMark semantics).

### M13. Model references are only validated for containing `/`

`chain.ts:155-158` + `switches.ts:198/226` + `interactive.ts:80`: `splitModel("prov/")` yields an empty modelID and `"/model"` yields an empty providerID; the three validation sites only check `includes("/")`, so bad values pass strict validation and only blow up at run time.

Fix: a unified validModelRef helper (both sides of `/` non-empty), shared by the three sites.

## Suggested fix priority

1. **H2/H3** (text-protocol verdicts) -- directly affect the correctness of completion verdicts, and the change is small (anchoring + reverse scan);
2. **H1** (orphan processes) -- every handover timeout keeps manufacturing incident scenes;
3. **H4** (error classification) -- decides whether a fault self-heals or hangs forever;
4. **H5/H6** -- deterministic failures in specific environments;
5. **M1/M2** go into the same remediation batch as the "rather block than wrongly let through" commit boundary.
