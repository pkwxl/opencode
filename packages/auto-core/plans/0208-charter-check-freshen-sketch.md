## D1 — the check that could not judge renders as unjudged (0165-097)

The record-time charter check (`checkTextAgainstCharter`, 0082 §10 D12) has three honest outcomes — skipped (no charter / no routing / no entry), consistent, flagged — and one fail-closed return that today *is* a `flagged` with the OPEN reading and a reason the type drops. The arm gets its own shape:

- **`CharterCheck` gains `{ kind: "failed"; reading: string; reason: string }`** — the fail-closed return becomes it. The strict reading rides along in the arm (not imported by the kernel-side caller): the ruled fail-closed direction keeps its force — the strictest reading is the one *in force* where the check cannot judge — but the arm's kind says what happened: nobody judged.
- **the admission warn (`admissionWarn`, D14b)** — a real flag keeps today's ⚠ line and today's `WARN — the planning input conflicts with the charter; in force: …` audit entry byte-identically. The failed arm renders its own: one ⚠ line — the planning input could not be judged against the charter, the reason, "no conflict recorded", the run proceeding (the composition-time gate still judges the composed whole — D14b's never-refuse posture unchanged) — and one audit entry in the plan verifier's own FAILED pattern (`verifyAuditEntry`'s `FAILED — <reason>`, the wall never implying a verification that did not run, 0113 D1): `FAILED — the planning input could not be judged: <reason>; no conflict recorded`. A WARN is a real flag's alone.
- **the clamp (`clampRecordedResolves`)** — the structural `ClampCaller` type gains the arm (structurally compatible with `checkTextAgainstCharter`'s widened return; `loop.ts`'s wiring unchanged). On `failed` the clamp still applies — the ruled direction (the wider grant never stays in force unjudged): the item is clamped to the arm's reading with the same `clampItem` path (the ledger mark and, for markers in process documents, the re-record — the re-recorded marker's "charter-clamped by the driver" tail stays true: the driver clamped it, fail-closed, per D12). What changes is the surfaced line: the ⚡ phase-boundary line gains the failure's name — `… the default in force is "<the strict reading>" (the check could not judge: <reason>); the recorded wider grant waits…` — so the person reading the boundary knows the strict reading is a fallback in force, not a judgment against their recorded default. A real flag's line stays byte-identical (the P10 floor).
- **the skipped arm's ledger mark is unchanged**: a skipped check (no charter, no routing, no entry) already marks the item checked without clamping — the degenerate floor D12 ruled; only the check that *ran and could not answer* clamps.

The finding's alternative — treating a fail-closed as skipped (no clamp) — is declined: it reverses the ruled fail-closed direction (a flaky endpoint would leave the wider grant in force, exactly what D12's strictness exists to prevent). The direction is the ruling; the silence was the defect.

## D2 — the freshen covers every source the remediation executor can rewrite (0165-098)

0156 D4's contract — every compose pass re-reads its remediable sources — was enacted over an under-enumerated set: the planning input and the brief. The executor's channel table (`editableSurfaceProblem`, 0082 §5 D7) passes more: the round brief, the analysis, the handovers (session handoffs and phase handovers alike), every process-document role — and the block map (`floorBlocks`) names exactly these as located sources, so a diagnosis can offer and the person can approve a remediation of any of them. The split:

- **the booking half reads once at entry** (0156 D4's residual reason, now scoped to what it truly covers): the prior-knowledge and previous-round digest texts, the cap decision, the one `statsDigest` booking — a per-pass re-read would double-book the planning session's sizes (the memory-service question's data) and re-print the injection line per remediation. `state` (the phase index) is driver-exclusive — no remediation rewrites it — and stays captured; `trimmedPhases` derives from it alone and stays captured with it.
- **the side-effect-free half re-reads before every compose pass** through the same one derivation (P5 — no second source): the joined handovers, the per-document handover list with its health findings, the round brief, the analysis. These are pure reads; the second pass now verifies what landed, for the sources the finding measured (the round brief) and their whole remediable family.

The digest half's own residual is named: a remediation rewriting `docs/R-NN/prior-kb.md` or a previous round's archived conclusions between passes still meets the entry-time digest — unmeasured (no case in the review), and the booking/cap-identity a per-pass re-read would cost is real machinery; P21 holds it until a consumer arrives. `appendPlan`'s compose already re-reads the round brief and the handovers inside each pass (verified clean in the review) and is untouched; its block map's omission of the round brief stays the S08-11 hygiene finding's own (step 075's family, not widened into here).

## D3 — the body reader strips the document's own terminator, never a quoted one (0165-099)

The terminator grammar is document-level — `endsWithEof` reads exactly the document's last non-empty line — and the todo/done reader's strip must read it the same way: **`taskBody` removes the document's own trailing terminator (the last non-empty line, when it is the mark) and keeps every standalone terminator line inside the body**. The old whole-body filter stripped every occurrence anywhere, so the format sketch the formulation todo's Scope teaches — the very shape the session is told to copy, terminator included — reached the session's prompt without its terminator, while the 0131 line beside it demanded one: the two teachings disagreed, and the stronger signal (the copied shape) was the wrong one. 0131's 38/38 incident now has its measured cause: the sessions copied a sketch that ended at `<acceptance: …>` — not a sketch whose terminator "reads as decoration" (the copied shape is the strongest teaching a prompt carries). 0131's own line stays exactly as landed (it teaches the rule; the copied shape now agrees with it), and its INDEX row is annotated with the corrected cause in this change.

The floor (P10): every ordinary document — one terminator, at the end — renders the same body as before, byte-identical; the strip's tail behavior over trailing blank lines is unchanged (`endsWithEof`'s own tolerance). The family: any task document whose body quotes the terminator on its own line (a report restating the protocol, a sketch like this one) now carries the quote as content — what a body *is*. Section readers (`scopeSection`, `acceptanceSection`) read between headings and are inert to the line.

The finding's other branch — rendering the sketch's terminator indented or fenced instead — is declined: it would teach a shape the format's own words call "exactly `<!-- auto: eof -->`", the goldens pin the sketch's present text, and the defect was never the sketch's; it was the reader's. The structural rule (strip the document's terminator, keep the body's) is the one home.
