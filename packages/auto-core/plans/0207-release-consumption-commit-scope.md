# 0207 — the release consumptions commit exactly what their name claims, and the person-boundary lines teach the recovery that works

Status: **active**. Ruled 2026-11-07 by 0166 step 047 (wave W8-planning), enacting 0165-013 (S07-06, S2, CONFIRMED — the release consumptions commit pathspec-less ahead of any clean-tree gate: transfer's project start (and m-mode plan's row 0d through the same `analysisGate`) folds the person's unrelated uncommitted work into the driver's `PLAN brief install` commit, unlisted; the round-brief install and `rederiveTail` sweep the same way just before preflight, so the run-start clean gate then passes over dirt it never saw — a later revert of "the brief install" takes the person's work with it, and the history misdescribes itself), 0165-187 (S07-05, S4, CONFIRMED — the person-boundary commands' failed-commit and crash lines teach a re-run their own refusals stop: adopt's "commit manually and re-adopt" meets "T-NNN is already done"; close's "then re-run" meets "already closed"; task-add's "a re-run would add it again" is false; a kill after the rename leaves the re-run refusing with the uncommitted close-out unnamed; a kill between clarify's write and its commit leaves "already released — transfer" pointing at a preflight that refuses the uncommitted survey) and 0165-188 (S07-09, S4, CONFIRMED DUP — the person-boundary stop lines' hygiene: transfer's proposal continuation re-composes the establishment pair inline beside `establishStopLines` (the one wording source 0102 built), the isolation failure line says "nothing was written" after earlier repositories switched, and the survey release line promises a brief install the survey may not carry).

This ruling Derives: **P4** (committing is the completion condition — the commit is
the audit trail and the rollback anchor, so a driver-trailered commit must
contain exactly what its subject claims: the brief install commits the brief
and its approved source document, never the person's in-flight edit; the
person's dirt meets the clean gate that exists to judge it, never a fold it
was never shown), **P8** (every surfaced line teaches the remedy it wants — a

one `commitTree` seam, its write surface derived from the drift itself; the

(recovery is re-derivation — the interrupted close-out is detected from disk
(the unit's `done.md` dirty in the tree, the released document uncommitted),

decorator's injection point — never a caller's argument" (see Premises; the
wall close breached it first under 0190 D2 with the comment left stale — this
ruling restates the rule: the decorator remains the only *injected* scoping,
and the caller-side pathspec is a conscious, enumerated family). Tier
touched: **mechanism only** — no principle change; the new stop-line wordings
are conscious vocabulary (P13's lockstep held by pinning every changed
literal in the same change, the byte-identical floor pinned for every state
the new conditions do not fire in).

## D1 — the three release consumptions commit their own write surface (0165-013)

The advance's release consumptions are the three commits that run ahead of
preflight's clean gate; each now takes a pathspec naming exactly the surface
its subject claims, through the one `commitTree` seam (the wall close's
0190 D2 shape):

- **the brief install** (`installBriefProposal`, both callers — the analysis
  release at the project start and the survey release at the phase
  boundary): `[BRIEF_FILE, source]` — the brief plus the document the
  approval was read from. The released document rides the install commit
  when the person hand-released it uncommitted (the walkthrough's "or add
  the line and commit yourself" half), so the commit that claims "the
  approved project brief (from …)" carries its evidence; a clarify-released
  or already-committed document contributes nothing (the pathspec matches no
  change for it). Inside the loop (the survey release's install) the tree is
  clean by preflight, so the pathspec is behavior-neutral there except for
  one ruled effect: the install no longer absorbs the completion rename and
  index tick of the phase it follows — the `PLAN transition` commit keeps
  them as the phase's close-out booking, the shape the manual suite already
  teaches and S04-02 (0165-072, step 076) demands; that finding's remaining
  half (the install-before-rename ordering) stays step 076's.
- **the round-brief install** (`installRoundBrief`, both callers — transfer's
  `applyReleasedBrief` and m mode's own establishment): the round's root
  directory `docs/R-NN` — round.md plus everything `establishRoundSetup`
  wrote (the phase index, the phase directories' seeds), the establishment's
  whole write surface, which is exactly what 0115 D3's "the round-start
  commit sweeps the uncommitted round setup" names. A person's unrelated
  dirt outside `docs/R-NN` stays for the next gate to judge.
- **the phase-sync commit** (`rederiveTail`): the phase index plus the
  drift's tail directories — `phaseIndexPath(round)` and every directory of
  `index.slice(keep)` (removed; the deletions must stage) and
  `planned.slice(keep)` (created; their seed files must stage) — the
  sync's own write surface derived from the drift it applies. The started
  prefix stays out by construction.

The floor (P10): over a tree clean apart from the committer's own writes —
every existing test's state — the pathspec stages and commits exactly what
`add -A` staged, byte-identical (the pinned subjects, log lines and end-state
porcelain unchanged). Over a tree holding the person's unrelated dirt — the
defect's state — the dirt stays in the worktree: at the establishment's G1
stop it becomes part of the person's own review commit (honestly theirs, in
their commit), and on every path that continues into the loop it meets
preflight's clean gate, which refuses it by name (exit 2) — the one gate
that owns judging dirt (P5), unchanged. The finding's alternative remedy
(clarify's D5 dirty discipline run before each consumption) is declined:
it would duplicate preflight's refusal one step earlier under a second
wording — a second home for the clean gate's judgment — where the pathspec
needs no new refusal surface at all.

## D2 — every person-boundary failure line teaches the recovery that works (0165-187)

The close-out order (writes, then commit) is unchanged — it is P4's shape,
and reordering it would be step 076's question, not this finding's. What
changes is that no line names a re-run the same command refuses:

- **adopt**'s failed-commit line: the unit is closed in the worktree
  (`done.md`, the index ticked) — the recovery is the person's one manual
  commit (`git add -A && git commit`), after which the run continues; no
  re-adopt is needed, and none is possible (a re-run refuses
  "`<id>` is already done"). The driver's missing `Auto-Stage` trailer is
  harmless — the next baseline starts at that HEAD (the finding's own
  measured evidence).
- **close**'s failed-commit line: the closing changes are in the worktree —
  commit them by hand, or revert them and re-run; a re-run over the same ref
  would refuse ("already closed") — the close itself is complete.
- **task-add**'s failed-commit line: the task is written but uncommitted —
  commit the left changes; the add is complete and no re-run is needed (a
  re-run now would refuse the dirty tree, and after the commit it would add
  a *new* task — the old line's claim, stated as the warning it is). The
  stale-handover arm keeps its line: nothing was added there, and its
  "commit manually and re-run" works.
- **the interrupted close-out, detected** (P6 — derived from disk, never a
  record): the re-run refusals that answer a killed close now recognize
  their own state — plan's `--adopt`/`--export` route over a done unit and
  close's already-done/already-closed arms append one ℹ line when the
  unit's `done.md` sits uncommitted in the tree: the close-out is complete
  in the worktree, the left changes are the person's one manual commit, no
  re-adopt/re-close is needed. The clean-state refusals stay byte-identical
  (the P10 floor; close.test's `toEqual` pins hold).
- **clarify**'s already-released arm reads whether the mark is committed:
  a survey carrying the mark while the document sits uncommitted (the kill
  between the write and the commit — or a hand release never committed) is
  taught the one manual commit ahead of the advance whose preflight would
  otherwise refuse it uncomprehendingly; the committed case keeps today's
  line byte-identical.

The finding's "better" branch — adopt/close re-committing their own
interrupted close-out on re-run — is declined on P4/P8 grounds: the close
re-commits through the same `commitTree` whose git just failed, so the
retry most often re-fails (the failing hook, the broken index) while
*appearing* to own the recovery; the person's manual commit is the
constitution's own recovery for a failed unified commit (P4's "unified
commit failure → block and halt, pending manual attention"), and the line
now teaches it truthfully at every exit — including the ones no line
previously covered. Revisit when a field round shows the manual commit
measurably failing (the trailer-less commit breaking a real close-out would
be the signal; the SHA-baseline audit's next baseline starts at that HEAD,
so no current reader breaks).

## D3 — the person-boundary stop lines' hygiene (0165-188)

Four items, three enacted, one declined:

- **the establishment pair's one wording home**: the `✓ round … established`
  and `✓ branch isolation` lines are extracted from `establishStopLines`
  into `establishedLines(round, setup, established)`; the G1 success block
  composes through it and transfer's proposal continuation renders the same
  pair through the same helper (its own ℹ proposal line and pointer flip
  stay continuation-side). Byte-identical output on both paths — the dedup
  is the whole change (0102's reflex completing the family it missed).
- **the partial isolation truth**: `isolateRound`'s failure arm carries the
  repositories already switched (`switched`); the establishment stop's
  failure line says so on the partial arm — `branch isolation failed after
  switching <repos> (content-neutral branches; the re-run's idempotent
  skips finish the rest), nothing else was written: …` — and keeps today's
  `branch isolation failed, nothing was written` byte-identical when
  nothing switched (the floor).
- **the survey release line's promise**: `gateStopLines` conditions its
  "the approved `## Project brief` section is installed" clause on
  `briefProposal(survey)` — the same extraction the install itself gates on
  (loop-phase's `installApprovedBrief`); a survey released without a
  proposal completes the phase and installs nothing, and the stop no longer
  promises otherwise. The proposal-present shape keeps today's line
  byte-identical (every existing pin's state).
- **the planPrelude row table**: consciously declined (P21 — machinery
  waits for its consumer). The finding itself framed it as "consider when
  the 0101 residue (S07-07) is removed" (removed at step 046/0206 D2), but
  no defect and no consumer locks the table's shape: the rows are pinned
  output-by-output in plan.test.ts, and a behavior-preserving 500-line
  restructure under byte-identical goldens is pure cost until a change that
  actually needs per-row structure arrives (the next row-affecting ruling
  names this residual as its first candidate for the reshape). The row
  numbers in comments stay the plan's own teaching.
