## AGENTS.md — Core invariants

- **Task units in the target directory** (unbolded standing rule, L105): "the phase's `tasks.md` is order and membership only (`- [ ] T-NNN <title>`), the unit files win over its ticks (`todo.md`/`done.md`, exactly one); the checklist lives only in `docs/T-NNN/subtasks.md`; runtime state (status, attempts, fork base) is `.auto/units.json`, never a document." — and the sync rule: "When changing the format, sync `test/tasks.test.ts`, the planning templates and the shell package's README format description."
- **Runtime dependency** (unbolded standing rule, L106): "Runtime depends on an external `opencode` CLI (spawn `opencode serve`) or `--server` to reuse an existing instance — or, with the claude adapter, on the `claude` CLI on PATH; the binary itself bundles neither."
- **Registry keys and env values are references, never literals** (L107): "a key is `{env:NAME}` or `{file:path}` and the driver never reads a referenced value into anything it builds — the reference reaches the managed opencode server through the spawn config and is substituted in the server's own process, and a resolved env value goes only into that child's environment." / "Logs, `models` output and error lines name the reference (`key 2/3 ZHIPU_KEY_B`, `env: HTTPS_PROXY`), never a value." / "The registry's project layer is local-only: init gitignores it, preflight refuses a layer git would commit (naming `fix`), and nothing but the operator writes either layer."
- **No environment-specific knowledge in tool source, ever** (L108, "standing"): "facts about a particular target project — dm-flash's `tests/` special treatment, any real project's paths or layout — never enter `auto-core`/`auto`/shell code, at present or in the future; mechanisms stay generic, and project-specific facts ride only the surfaces the target directory itself declares (config `scanExempt`, intent packs and bundles, `brief.md`, the roadmap)." / "A change that would need to name a real project is the signal to find the structural rule instead — 0108 replaced dm-flash's `test/*` first-aid exemption with the structural deliverable definition (what a nested destination repository's git manages) exactly this way."
- **Exit codes** (L112): "`0` complete / `1` usage or environment error / `2` blocked or reverted to pending for human attention / `130` force-quit by two consecutive Ctrl+C."
- **Constitutional project attributes** (L113, unbolded heading): "are fixed into the target directory `.opencode/auto/config.json` by init only (changed per key by `amend`, repaired by rule by `fix`, which never resets a key — plans/0052 D10/D25); appearing at run time is exit code 1; a bad config file fails strictly, unknown keys are ignored; `init` validates everything before its first write (plans/0052 D7)". / commit prerequisite: "inside a git work tree, init refuses (exit 1) when git cannot commit there (`commitIdentityProblem` in `src/git.ts`: no user.name/user.email resolves), because the unified commit is the completion condition". / tombstones: "`--source-dir/--source-path/--dest-dir` and the config keys `source`/`destDir` were retired on 2026-09-23 (plans/0052 D1–D3) — usage error / strict failure, and both key names are permanent tombstones." / "A full-overwrite `init` drops a stored retired key and names it with its value instead of failing (D4)."
- **Committing cannot be turned off** (bolded inside L113): "any `--commit` form is a usage error; a stored `commit: true` loads and is ignored, any other stored value fails strictly with the retired message (`fix` drops it). Committing is the completion condition; the commit side idles only under dryrun and in non-git environments (tests install the no-commit double through the git service seam)."
- **driver-exclusive state writes** (L114): "the index ticks and the `todo.md` → `done.md` renames are written only by the driver — under parallel lanes the parent re-derives the index ticks at landing (`syncIndexTicks` on a `Auto-Stage: landing-sync` commit, 0068 D6); AI sessions must not edit them; during `run` the config files and AGENTS.md are read-only (src/protect.ts lets the driver's writes through)." / "There is no task mirror: the `CURRENT.md` mirror retired (plans/0054 D3; preflight deletes one an earlier release left), every prompt inlines the task and `docs/T-NNN/todo.md`/`subtasks.md` carry it."
- **Project brief is driver-written state** (L115, unbolded standing rule): "it sits in `PROTECTED_FILES` (read-only during a run), written only by the seed (`init/amend --brief`), the survey gate's install of the approved proposal (D15.2) and `fix`'s retired-key move; a person revises it through those commands, never by hand mid-run."
- **AGENTS.md holds only the driver's block** (L116): "init/amend/fix/run render it from the config; sessions never maintain the file (it is gitignored, so their edits would escape the unified commit and the unit rollback) and rounds never snapshot it (`AGENTS.md.bak` retired) — durable knowledge goes to committed `docs/` documents." / "Retired flags and keys (`--verify`, `--review`, `--early`, `--early-review`, `--final-review`, config `verify: true`, the retired session role keys) are usage errors / strict failures (plans/0044 D1/D2)."
- **Process documents are not design dependencies (P1)** (L117): "the deliverable is the nested destination repositories' own files (plans/0108 — everything the working directory holds outside them, test tooling and `prompts/` included, is process workspace, never reference-scanned)" / "every reference to the process side is a finding: a process-document path (`docs/T-*`, `docs/R-*`, `.auto/`), a bare task id, a path leading outside the repository's own root" / "`the destination must not reference process documents` is release-time truth alone" / "AUTO-* marker lines may appear in code comments but must be self-contained." / "The findings are what the rounds only record, as one aggregate count line (the close-out ⚠ and the round-close warning — plans/0109: the per-finding ledger was verbose and unreadable; the release gate's itemized output is the fix list), with the treatment deliberately delayed; the shell's `release` command is the enforcement moment, refusing while any remains; the outer workspace names tasks freely, no task-id check runs there." / "The remedy for every such finding is restatement (0106, sharpened 0108 D8): the fix rewrites the **true information the reference implied** — read from the task document or path it pointed at, written out self-contained in the destination's own terms — and then removes the pointer; deleting the id or path without carrying its information across is not a fix (never delete the record the id anchored)."
- **Unified commit** (L118): "AI sessions must not run commit-type commands; after a session ends the driver commits all changes recursively via src/git.ts (nested sub-repos first, then this repository)." / "**Committing is the completion condition** (plans/0021): unified commit failure → block and halt for human attention; starting an execution unit (task/subtask/standalone hidden task) requires a clean worktree (driver-state leftovers self-heal, other dirty areas block for human; run start follows the same rule)" / "close-out validates via the SHA baseline that the commit range contains only driver commits (Auto-Stage trailer)" / "resumed runs are exempt from the clean check."
- **Completion is never judged by agent self-report** (L119, unbolded heading sentence): "subtasks are ticked by the driver from the state files; a unit is done only when its artifacts are on disk and committed (③ commit / ④ dirty, git.ts commitPending/beginUnit), or when a person closed it with `close` — its `Closed:` field records why." / "Checking work is planned work (acceptance tasks, the v phase); its verdict reaches the driver only as the report result line, and a FAIL stops the run for a person to accept it with `close` or rework it (plans/0044 §3)."
- **Experiment switches read the environment only, never persist to disk** (L120): "the `OPENCODE_AUTO_*` environment-variable layer (parsed inside the core in src/switches.ts, zero CLI shell changes) writes no state files; experiment semantics = this run only; constitutional keys do not enter ProjectConfig before promotion."
