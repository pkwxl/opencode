## 0053-lifecycle-commands-design
- Date: 2026-09-23 (Status header: "the design pass below is the 2026-09-23 pre-code pass"; git add-date 2026-09-23; banner corrected 2026-10-02 by plans/0069 §4.2 A6)
- Trigger: The P3 design pass that 0052 §6 requires before any P3 code — the detailed design of the lifecycle commands (`plan`, `close`, append planning, the run lock, lifecycle-leaf `init`), answering 0052's open questions Q1–Q6 and listing every departure from a 0052 decision for ruling.
- Rulings:
  - D1 — Run lock is `.auto/run.lock`, one JSON object `{pid, host, command, started}`; driver-internal, never committed, never read by a session; the hostname is recorded (Q3) and a foreign-host lock counts as live. (§3.1 D1)
  - D2 — Lock semantics (new `src/lock.ts`): atomic creation via `link()` to a temp file; stale-lock detection by pid probe (ESRCH/EPERM); unparsable treated as live; re-entrant per process and directory; release in `finally` plus an exit handler; one accepted residual race recorded, not engineered away. (§3.1 D2)
  - D3 — Who locks: `runAll` acquires for `run` before preflight; `plan`/`close` acquire themselves; `init`/`amend`/`fix`/`reset` refuse (exit 1) while a live lock is held; `check`/`status` never lock, `status` prints the live lock. (§3.1 D3)
  - D4 — `plan` decides every route that needs no AI before it starts an agent: `planPrelude` in new `src/plan.ts`, rows checked in order, first match wins; it runs on the dirty tree a fresh `init` leaves and never starts a server just to print a notice; G8 failure exits 2, not 1. (§3.2 D4)
  - D5 — Input on a round-setup route is refused before any write (exit 1), the message naming the order establish → commit → input. (§3.2 D5, Q17)
  - D6 — `RunAllOpts` gains `stopBefore?: "execute"`, `planInput`, later `append`; nothing changes when `stopBefore` is absent (`run` byte for byte); after a planning step the loop returns 0, the stop being the review point. (§3.3 D6)
  - D7 — `plan` on an execute route (phased): exit 0 with a notice without input (keeps `plan && run` usable in scripts); exit 1 with input — a real mistake because the person thinks the phase is unplanned (departs from 0052 D14 "refuse"; Q9). (§3.3 D7)
  - D8 — Reaching `complete` inside the loop does not open the next round: `plan` prints the round-close report plus a `next:` line and exits 0; a just-completed round cannot have `## Close` filled yet. (§3.3 D8, Q18)
  - D9 — One `plan-input.md` per phase directory, the latest input verbatim, committed by the driver on its own before the planning unit (Q1: earlier inputs live in git history); an unchanged text means no write; a different text replaces it and the step runs in a new session. (§3.4 D9)
  - D10 — New document role `planningInput` (`{eofScan: false, process: true}`), matched by path regex; without it the file would classify as artifact and fail the eof scan. (§3.4 D10)
  - D11 — The input reaches the session through an optional `{{#if input}}` block in `phase-plan.md` (not a tier-1 marker, older overrides keep loading); m mode reuses `implement-plan.md` unchanged over the persisted file; a template without the slot logs a warning. (§3.4 D11)
  - D12 — m-mode planning runs on `planPhase` (one planner); `spec.role` stays `implement-scan` so routing configs stay valid; the open-step precedence moves before the m-mode branch; strict resume gets the role pass-through; the `implement-plan` stage value retires. (§3.5 D12)
  - D13 — `implement.ts` is deleted in P3a and `--implement-file`/`--implement-prompt` retire with it as `RETIRED_FLAGS` (departs from 0052 D20's P3c; Q10). (§3.5 D13)
  - D14 — Shell `plan [dir] [-p|--prompt <text> | --file <path>] [session flags]`: flag order, mutually exclusive input flags, refused config flags, lock, prelude, then `runAll` with a shared run-options builder. (§3.6 D14)

  - D17 — `closeUnit` targets (R-NN / R-NN.P<nn> / T-NNN, current round, open only), explicit dependents refuse or join under `--cascade`, implicit dependents count as satisfied, subtasks are not cascaded into (departs from 0052 D17; Q11); the mechanical handover is driver text, not an overridable template.   - D18 — What `close` writes, tasks first then phases in index order: `Closed:` inserted as the field block's last line, `renameUnitDone` and index tick; a phase close bypasses `completePhase` on purpose — the gates are skipped and recorded, never passed; a closed round relaxes only G8's completeness precondition.   - D19 — Records cleared: only those of closed units (departs from 0052 D17's "every resumable record"; Q12) — units.json entries, progress.json, handover.json, test-handover chains, CURRENT.md; `.auto/next-task` untouched. (§4.2 D19)

## 0055-model-registry-and-tier-routing-design
- Date: 2026-09-25 (Status: "design, ruled (2026-09-25; revised the same day with the follow-up requirements…)"; S0–S1 done 2026-09-25, S2–S6 done 2026-09-26; git add-date 2026-09-25)
- Trigger: The user's request of 2026-09-25 (8 items + 5 follow-ups): phases/sessions get different default models by reasoning depth; disabled-time windows with failover/failback; a model bound to one agent; several API keys rotating on quota; internal model names with configuration outside opencode's own; externally authenticated agents the driver only invokes — plus kimi k3-256k→k3 seamless continuation, the later hibernate retirement, a project-local registry override, proxy env for agents, and a free model reading failure messages before retries exhaust.
- Rulings:
  - §3 — The split: the tier belongs to the work (the program declares it for builtin sessions and phase types, the project for custom types); the fleet belongs to the operator and lives in an operator-level registry outside the target directory and outside opencode's configuration — settles 0017 U1. (§3)
  - §4.1 — Operator layer `$OPENCODE_AUTO_MODELS`, else `$XDG_CONFIG_HOME/<configDir>/models.json`; optional project layer `.opencode/auto/models.json`, local-only like `opencode.json` (init gitignore entry, `fix` rule, preflight refusal when git does not ignore it, read-only during `run`). (§4.1)
  - §4.1 — Merge one level deep: name-keyed sections replaced whole per key, `null` removes, nothing merges inside an entry; validation on the merged result, each error names its layer; either layer alone is a registry, without both there is none (C2). (§4.1)
  - §4.1 — Read once at run start like the switches; the driver only reads the layers, never writes or locks them; the run lock does not cover the operator layer. (§4.1)
  - §4.1 — Strict validation: bad JSON, an unknown field inside an entry, or a broken reference fails the run start with exit 1 and names the field; unknown fields are not ignored, unlike `config.json`. (§4.1)
  - §4.2 — Format: agent profiles (`adapter`/`bin`/`env`/`server`), model entries (`agent`, `model`, `wider`, `variant`, `context`, `avoid`/`only`, `keys`), `tiers` deep+simple (a model may appear in both), `routes` overrides over the default tiers (`*` not allowed), `classifier` list, file-level `tz` default UTC; internal names `^[a-z][a-z0-9.-]*$` contain no `/` so they never read as raw `provider/model`; an entry without `model` is allowed (a registry that only pauses). (§4.2)
  - §4.3 — Keys are references only (`{env:NAME}`/`{file:path}`); the ring belongs to the provider (entries on one provider declare the same ring, two different rings a load error); rotation is a managed-server restart through `setConfig`, sessions persist across it; the ring position never moves back while the current key works; rings are inactive under an external server. (§4.3)
  - §4.4 — Windows: grammar `[days ]HH:MM-HH:MM`, `avoid`/`only` mutually exclusive; windows gate dispatches, never running turns; the machine clock, DST first-instant rules; the S1 settle adds wrap-around day ranges, the 8-local-day search horizon. (§4.4)
  - §4.5 — Context steps (R12): one entry with `wider` steps, not two linked entries; the entry is the unit of routing; step-up at window − max(48k, window/5) via a model-naming steer; one-way within a session, every new session at the base step, resume recomputes from context size; the cache claim is checked at the first step-finish; `wider`/`variant` rejected on claude at load in v1. (§4.5)
  - §5 — Default tier tables (R4): planning roles deep; `whole`/`subtask` take the phase type's execute tier; wrapup/handover/knowledge/bypass simple; analysis/design/acceptance deep, implement/test simple, custom types `Reasoning:` field with absent = deep. (§5)
  - §5 — Borrowing (R3): a simple session may continue down the deep list (availability over cost); a deep session never borrows a simple model — it waits. (§5)
  - §6.1–6.2 — Selection: the candidate list (route override > tier, simple lists borrow deep); a candidate is usable now when it passes the agent filter, its windows, no down mark, its provider's ring has a usable key, and its (top-step) window fits the project cap; a new prompt takes the first usable, a continuation keeps the chain's model while usable. (§6.1–6.2)
  - §6.3 — Nothing usable: wait for the earliest window opening (in-unit sleep with hibernate's jitter, force-quit by double Ctrl+C) or the existing wait-and-probe loop; a tier the run's phases need with no candidate after the filter is a preflight error, never a silent wait. (§6.3)
  - §6.4 — Down marks live in memory only (a new run starts with every model eligible), cleared at `FAILBACK_SCOPE` boundaries and by `/failback`; a cleared key mark never moves the ring back; a reset time makes a mark last until then. (§6.4)
  - §7 — Escalation order key → model → wait: a quota/auth/rate error rotates the key and re-dispatches the same model from a fork; otherwise the model is marked down and the next usable candidate selected (a cross-agent move is a new session with the worktree-check note); with nothing usable, wait. (§7)
  - §7.1 — The classifier (R14): asked only where the patterns are not decisive; raise-only merge (never lowers a class); one JSON-line reply (`class`, `resetAt`); a 30 s timeout or parse failure is no answer; answers cached, at most 20 calls per run; runs without tools (`bare` → `tools: {"*": false}`), opencode entries only in v1; sees only redacted error text truncated to 2,000 characters; its own failures are classified by the patterns alone and mark only the classifier entry. (§7.1)
  - §8.1 — Agent pool: one lazily started host per agent profile — a profile nobody selects never spawns; every driver call resolves its client from the chain's agent; `opts.server` becomes `ServerControl`; the opencode spawn moves in-driver so profile `bin`/`env` apply. (§8.1)
  - §8.2 — Sessions are bound to their agent: `SessionChain.agent`, persisted session ids gain their agent; an absent field means the default agent, so every record written before the change stays valid; any registry writes the new field shapes, without one every file is byte-identical. (§8.2)
  - §8.3 — A session never crosses agents (no fork, no resume); a move is a new session on the target agent with the worktree-check note; on resume the recorded session is used only if its agent's model is usable, else it is a dead session. (§8.3)
  - §8.4 — Fork base per agent: `forkBase` becomes a map agent → id, rebuilt deterministically from `context.md`; the base is built with the model selected for the `subtask` route; resolved inside the subtask loop for the chain's current agent. (§8.4)
  - §8.5 — Capability degradation becomes the intersection of the capabilities of every agent with a candidate after the filter, each note naming the forcing agent; per-session degradation rejected. (§8.5)
  - §8.6 — Each adapter translates the agent contract and the permission rules itself and supplies `errorPatterns`; a new adapter is not done until both translations exist. (§8.6)
  - §8.7 — External authentication: the driver never logs in, never reads credentials, never passes secrets; preflight only checks the referenced profile's `bin` runs under its env; an expired login surfaces as an `auth`-class error and the probe loop continues without a restart once the operator logs in again. (§8.7)
  - §8.8 — Agents not supported yet: one design each with a measured fact baseline (like 0041) under `src/agent/<name>/`; `registerAgentAdapter` in `src/shell.ts` lets a shell add an adapter without touching the core; check for a common protocol (e.g. ACP) before writing per-CLI adapters. (§8.8)
  - §8.9 — Account failover for external agents: two profiles differing only in `env` (`CLAUDE_CONFIG_DIR`), both logged in outside the driver, listed in the tier — plain model failover. (§8.9)
