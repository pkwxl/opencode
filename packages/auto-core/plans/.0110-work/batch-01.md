## 0001-auto-number-design
- Date: 2026-09-04 (own header note: code and follow-up work complete 2026-09-04); revision 2026-09-07; git add 2026-09-19
- Trigger: Under the default behavior every phase-planning session renumbers tasks from T-001 with no persisted record, so task numbers repeat across phases/rounds and clash in artifact filenames (docs/T-NNN.*.md) and commit messages.
- Rulings:
  - Switch tier = init constitutional level: the `autoNumber` key of .opencode/auto/config.json (boolean, then default false); init/continue accept the pair (amend semantics); any appearance on run is exit code 1; both switches present with neither carrying `=false` is a usage error. (Confirmed Decisions 1)
  - Record store = the .auto/next-task state file: content one positive integer (next available number), maintained by the driver; .auto/ gitignored so fresh clones lack it, which is exactly what triggers recovery. (Confirmed Decisions 2)
  - Recovery timing = recover first then continue, lazily right before the phase-planning session (planPhase entry), not at run start; m mode has no planning session so no effect (init prints an ℹ notice). (Confirmed Decisions 3)
  - The phase-planning session is the only numbering consumption point: ensureNumbering → numberStart injection into phase-plan.md → collect validates all numbers ≥ record start → advanceNextTask to this run's max +1. (Mechanism Design, bullet 1)
  - Record recovery ladder: valid record used directly; missing → deterministic floor taskNumberFloor (scan current/archived PLANs and docs artifacts, parse failure degrades to regex); floor = 1 → write 1 without a session; floor > 1 → one-shot side-channel AI recovery session (number-recovery.md, pseudo-task PLAN, requireArtifact, stage=numbering) validated against the floor, retry once then silent block. (Mechanism Design, bullet 2)
  - T-F<k> final-review numbers are a separate derivation namespace and never enter the auto numbering record (taskNumber only accepts pure digits). (Mechanism Design, bullet 3)
  - addendum: Revision 2026-09-07 (stable-refs P3 / D5) — the `autoNumber` default flipped false → true (`--no-auto-number` the retained opt-out); mechanism otherwise unchanged; "default = --no-auto-number" phrasings below reflect the pre-flip historical baseline. (header revision note)
- Supersession: none seen beyond the in-file 2026-09-07 revision note recording the default flip (a baseline change, not a retirement; the doc self-declares pre-flip phrasings historical).
- Principle candidates (verbatim):
  - "task numbers (T-NNN) **never repeat** in the target directory; when the key numbering record (.auto/next-task) is missing, an AI session can derive the appropriate next task number to recover the record." (Goals, --auto-number bullet)
  - "on success `advanceNextTask` advances the record to this run's maximum number +1 (increase-only, never decreasing)." (Mechanism Design, bullet 1)
