### S1/S2 failure scenarios

- **S10-02 (S1).** (1) A checklist subtask (mode true, an auto stream, or a hand-written item) ends with `docs/T-NNN/handoff.md` saying `Status: done` and its declared artifact missing. (2) The shape check fails, the fork re-prompt fails, the unit blocks: "artifact shape check failed (hidden blockage) … Check the artifacts and re-run". (3) The loop's blocked path commits the interruption scene, handoff.md included. (4) The person re-runs. The record is summarized, so the pipeline's cleanup removes only untracked copies. (5) runSubtask reads the tracked `Status: done` and logs "marks the subtask complete; checking it off directly". The driver then renames todo.md → done.md, ticks, and commits with no session and no shape check. (6) Under `--no-wrapup` the task completes with the artifact missing; otherwise only the verifier is left to catch it.
- **S10-03 (S2).** (1) Mode `off`. The whole-task session ignores "without decomposing it into subtasks" and writes a 7-line `subtasks.md`. (2) `unjudged()` returns nothing because there is no clause, and the stage commits the file. (3) The subtask loop treats the checklist as the person's and dispatches 7 more sessions with no 2–5 bound and no guard.
- **S10-05 (S2).** (1) Every session of a scope writes a fresh handoff.md ending `Status: continue`. (2) handoverVerdict says `continue` each time; nothing counts or warns. (3) The chain ends only when the agent writes `done`. The person is never the terminal.
- **S10-07 (S2).** (1) Session 2 hands over validly (`Status: continue`). (2) Session 3 hits the wall, gets the hint, and ends without writing. (3) `due` is true, so freshness is never checked, and session 2's consumed document is read as session 3's handover ("handed over as docs/T-001/handoff.md"). (4) Session 4 continues from next steps two sessions old. The retry built for exactly this miss never runs. Variant: if session 3 had written a fresh document without a status line, it would block as "failed twice", because session 1's resolved miss had spent the scope's only retry.
- **S10-08 (S2).** (1) Doc lanes, width 2. Units A and B run in one tree; B has already landed a share. (2) A's session passes the wall without a valid document. Strict resume is on (the default), so rollbackRedo runs. (3) rollbackUnit runs `stash push -u -- .` over the whole tree, B's in-flight files included. It then runs `reset --soft` to A's baseline, which retracts B's landed commit, and stashes the reclaim too. (4) B's session keeps writing into a tree missing its work. Its close-out fails or quarantines, and recovery is a hand job from `git stash`.

## Design notes

- Health: the handover engine is the area's best idea (one verdict step, scopes parameterized, the AUTO-DECISIONs explain every asymmetry). Its weakest choice is that the handover document has no owner lifecycle. One task-level `handoff.md` is shared by the whole stage, serial streams and fix rounds, written by sessions, committed by three different commits, and deleted by only two of five scopes. Every reader trusts presence: S10-01/02/07 are one defect family.
- First change: give the document a lifecycle the driver owns. The writing scope retires it at its natural end, recovery reads it only with a record naming that scope, and the engine requires freshness on every non-natural verdict. Then re-arm the retry per handover and decide the chain bound (S10-05, a W0 ruling shared with S11-02).
- The strict rollback redo is a tree-wide git operation reached from the innermost loop. It should be guarded where it lives (rollbackUnitState), not by each caller (S10-08).
- "Who may write the checklist" is unruled outside the clause (S10-03). The split guard is careful; the no-clause path has no guard at all.
