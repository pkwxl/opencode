## Design notes

The ops layer is a disciplined mirror of the CLI (its header constitution is unusually explicit, and the gates/confirm separation is better than the CLI's -f bundling) — but the mirror is maintained by hand, and the three parity defects (phases on amend, the git bootstrap, the 0122 stamps) are exactly the places where the CLI grew a rule after the mirror was written. The observation side is the healthiest part: the defensive-read caveats are documented, implemented and tested; the one P12 hole (clean-on-git-failure) is a two-line fix. Best choice: the question journal's durability model (in-memory queue + journal replay + start compaction). Worst: served-line vocabulary — the core teaches CLI verbs under a bin that has none (S30-04), the same family as S29-08's banner drift. Change first: the one-core-init-sequence lift (S29-04's remedy) — it dissolves S30-02 with it.
