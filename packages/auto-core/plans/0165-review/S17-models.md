**S17-01 — the forward walk, step by step.** (1) Ring [A, B] on provider P, position A. A's quota fails → rotation to B, A held 5 min. (2) B fails before A's hold passes → the search refuses; B held; position B; every key held. (3) §6.3's probe clears *all* of P's marks (position stays B) and succeeds on B. (4) B fails again (its 5-hour window really is spent) → the order-first search lands on A, which carries no mark; B held 5 min; position A. A works. (5) Six minutes later a new session starts: ringWalk scans A (no mark → skip), then B (mark passed, index 1 ≠ from 0) → walks *forward* to B: commitWalk, setConfig, server restart. (6) The session's first call fails on B → rotation back to A (still unmarked) → a fork re-dispatch and a second restart. Steps 5-6 repeat at every hold expiry for the rest of B's window.

**S17-02 — the walk under doc lanes, step by step.** (1) A doc-eligible phase runs two lanes in-process on one AgentPool (loop-task.ts:1457). (2) Earlier in the run key A failed (unstated) and the ring rotated to B. (3) Lane 1's session is mid-turn on B — a long agentic turn streaming tool calls. (4) Five minutes after A's mark, lane 2 opens a new session: walkProviderKey finds A's hold passed → commitWalk, setConfig, `host.restart(…)` on the shared opencode server. (5) Lane 1's server dies under its turn: the event stream drops, the session layer classifies a network failure and runs its own restart-and-fork — re-buying the turn's progress and, if lane 2's first prompt is already in flight, killing that one in turn.

## Design notes

- Health: the secrets half is careful where it was designed (references in the spawn config, the parse scrub, names-only lines) and leaky only at its edges — name positions (S17-05), URLs printed outside `models` (S17-04), and a family statement that no longer matches the code it governs (S17-06). One display rule with one home would close the first two.
- Best choice: decide-then-commit for every ring search (router.ts AUTO-DECISION) — the searches are pure, replayable and unit-testable, which is exactly why S17-01/S17-03 reproduced in thirty lines.
- Worst choice: 0163 shipped its three measurement claims ('a restart only when an earlier key's mark passed', 'oscillation cannot happen', 'pre-first-call so no in-flight work') as prose, none pinned — each is false in a reachable state (S17-01/02/03). The key is a property of a *shared* managed server; every restart trigger needs a safe-boundary rule under doc lanes.
- Change first: bound the walk to `index < from` and skip it on a rotation-seeded fork (one wave, three pins), then make restart-under-siblings a pool-level gate (S13/S16 own the failure-rotation half).
- The project registry layer can name the agent `bin` the driver spawns; it lives in the target directory, guarded by a chmod that protect.ts itself calls 'a guardrail, not a security boundary' (a session can also create the file when absent). Consistent with the same-user posture; under 0162's confinement the layer is the one path from agent-written bytes to a driver-spawned executable — a question for S32, not a finding here.
