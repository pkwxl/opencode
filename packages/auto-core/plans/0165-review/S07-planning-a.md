  `clarifiedMark` true (the trimmed indented line), so run prints "✓ phase boundary: … complete at a clean phase

  `installApprovedBrief` writes the agent's proposal into brief.md as "approved", the phase closes; the fork's
  default is now in force for every later round.
- **S07-02 (S2)** — 1. A phased project established R-01 with `OPENCODE_AUTO_ANALYSIS=off` after the first transfer
  stubbed docs/analysis.md (or the person later drafted an analysis). 2. The survey holds; the awaiting stop names

  survey cannot be released by the command); with a valid draft it writes and commits `Clarified: yes` on the
  analysis, prints "R-01 opens under the roadmap's line", and the survey is still held — the roadmap now governs
  the round's tail at the next transfer.
- **S07-06 (S2)** — 1. At the project start the person has a half-done edit in src/main.ts and a scratch file, writes
  `Clarified: yes` into the analysis by hand. 2. `transfer` → analysisGate → installBriefProposal commits

  3. Later a `git revert` of "the brief install" removes the person's edit too; at a boundary, rederiveTail and the
  round-brief install sweep the same way ahead of preflight, so the clean gate never sees the dirt.

## Design notes

- Health: the commands are refusal-first and carefully worded; the shared emitters (0102/0105) work. The weak seam
  is the **person mark as a whole-document grammar** in documents an agent writes (S07-01; with S12-02 and S04-06
  three gates of one family) and the **pathspec-less driver commits at the person's boundary** (S07-06, S04-02).
