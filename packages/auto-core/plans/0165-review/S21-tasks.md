**S21-01 scenario.** (1) A target's nested destination repository `dest/` has (or a session adds) a file
`dest/docs/handoff.md` — an ordinary name for a project's own hand-over notes. (2) A work session writes into it "the
rationale is in docs/T-012/report.md". (3) At unit close-out processReferenceScan sees `dest/docs/handoff.md`, roleOf
returns `handoff` from the file name alone (roles.ts:221-222), p1Scope is false, the file is skipped — deferredCount
stays 0. (4) At the person's `release`, the same scan under the release posture skips it again: the gate passes, and
the shipped repository depends on a process document that will not exist (P1-a broken, the enforcement moment silent).

**S21-02 scenario.** (1) T-001 is in progress; its session (bash allowed, `.auto/` guarded by the prompt contract alone),
or the person by hand, writes `.auto/units.json` with `"T-001": {"status": "done"}`. (2) The next loadPlan returns T-001
as done though `docs/T-001/todo.md` is still the unit file (tasks.ts:533) — 0047 R1's "done exactly when done.md
exists" no longer holds. (3) next() skips T-001; T-002 (Depends on it) runs on unverified or absent work; status shows
✓. (4) Nothing in git records the closure (`.auto/` is ignored), no done commit exists, and every later load repeats
it until the entry is removed by hand. A string `attempts` further corrupts the dispatch count (`"7" + 1` → `"71"`).

## Design notes

- Healthy core: one unit model for three levels, permanent paths from one constructor module, files-win precedence applied uniformly, a graph check with path-naming cycle reports, atomic runtime writes. The CRLF floor 0158 claimed holds across the scope.
- Worst choice: **the classifier and the readers trust shape too broadly at the edges** — a name-based role match escaping its namespace (S21-01), a runtime read cast instead of sanitized (S21-02), a parse failure treated as "nothing recorded" after the file became the lane registry (S21-03). Each is the P12 "uncertain reads toward dirty" rule applied at 0047's vintage and not re-applied when later rulings (0068, 0096, 0108) widened what the read means.
- The field block is the strictest grammar with the weakest near-miss discipline (S21-04): the analysis/roadmap grammars got near-miss scans (0084, 0158), the unit field block — the one the scheduler and the park gate consume — got none.
- The role table's channel discipline is uneven: gaps.md got its own role "so the path never doubles as the handoff channel", report.md — the only completion verdict (0124 "reserved", S11-01) — is a plain artifact; a verdict role is the natural home for S11-01's ownership check.
- Change first: S21-01 (one line moved, P1's release gate) and S21-02 (two sanitizers), then the near-miss scan of S21-04 with S21-05's one-home ruling.
