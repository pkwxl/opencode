- **Atomic fresh acquisition** — lock.ts:107-120 writes a pid-named temp file and link(2)s it into place (EEXIST =

- **Re-entrancy and release** — one count per resolved root, each handle counts once (`released`), removeLock deletes

- **Lock families across shells** — the CLI refuses init/amend/reset/clarify/sync/fix (dryruns exempt) on a live
  lock. plan, close, land and transfer acquire it, and run acquires inside runAll. The server's config ops refuse, and

  finally, requestExit wakes every sleeper (exit.ts:99-154); the transport cannot reach a dead holder (`live` set at

## Design notes

- Healthy core: the per-run Control (wakeable sleeps, a boundary vocabulary in a leaf) and the holder are a clean
  P5 move, and the link(2) acquisition is correct.
- Worst choice: the sideband's target is attach-only state, with no detach at a turn's end. Between turns the 💬
  line becomes an unwatched agent channel (S06-01).
- Second worst: liveness is (hostname, pid), and the own-pid shortcut resolves toward "stale" (S06-06). The lock,
  the lane orphan probe (S05-04) and the daemon's host-side check are three readings with two rules.
- The signal story is SIGINT-only and arms late (S06-07, S06-08). One force-terminate body behind SIGINT, SIGTERM
  and SIGHUP, installed before the first sleep, closes both findings.
- D2's acceptance is cheap to retire: remove a stale lock by rename-to-unique and re-read, so a racing acquirer
  never deletes a fresh lock.
- Fix first: S06-05 (a one-line launcher fix that unblocks the shipped binary's lanes), then S06-01, then the
  signal body, then S06-02 (both planned waits on sleepUnlessExit).
