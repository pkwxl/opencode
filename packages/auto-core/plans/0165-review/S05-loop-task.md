## Design notes

- Health: the worktree lane path is the mature half — a pure readiness core, one failure matrix, re-entrant landing.
  The doc loop is the fragile half: it inherits the single-slot progress record and the tree-wide rollback, and its
  recovery (D10, 0156 D1) is only exercised for the unit that holds the record.
- Best choice: landLane's five serialized steps with the parent as the sole merger, and the records persisted
  before the sync commit (0156 D6) — every crash window re-derives.
- Worst choice: the recovery reads (D14) trust liveness signals instead of the evidence on disk — the pid
  over the report (S05-03, S05-04), the string over the directory (S05-08), the record over the leftover (S05-02).
- P21: the probe-form /exit under concurrency (exitLabel in both lane loops, 0143's lane reasoning) has no consumer —
  D11 refuses every /exit channel at width ≥ 2. Built machinery waiting for a relay-steering future.
- The straggler prune force-deletes (`branch -D`, git-worktree.ts:228) a branch whose worker finished after the
  ms-wide window between spawn and setLane — work destroyed only under a parent-only kill in that window; noted, not
  a finding.
- What to change first: S05-02 with S10-08 (one wave: the flatten owns every leftover; the rollback guard in
  rollbackUnitState), then S05-03/04/08 (recovery reads evidence), then S05-06 (rule the repair boundary).
