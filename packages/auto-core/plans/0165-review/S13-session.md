**S13-01 — a driver-side throw loops forever.** (1) A run's `.auto/` becomes unwritable (disk full, a permission change) or a concern/sideband throws. (2) attempt's `remember()` (or the throwing code) raises after the prompt ran; runSession's catch makes it `session error: EACCES …`, no class. (3) nextStep → `retry` ×5 (0,1,2,4,8 min), each a fresh session executing the whole prompt. (4) `after-ladder` → failover (if any) → awaitRecovery: the probe chain has no phase, never writes the record, answers ok → "service recovered", ladder reset. (5) Back to (2), indefinitely; the person sees only repeating lines until Ctrl+C.

**S13-04 — a mid-turn kill loses the claim.** (1) runner persistStage writes `{active:false, phase:whole}`. (2) attempt dispatches on opencode; the POST is pending for the whole turn; `remember()` waits behind it. (3) The person double-presses Ctrl+C (or the host dies) mid-turn; the session has edited files. (4) Re-run: the start gate finds dirt, the record is not active → "handle them manually (commit or clean) and re-run", exit 2. (5) "clean" destroys the killed session's work; "commit" leaves a foreign commit, and the stage restarts in a new session without the killed session's context.

**S13-06 — an overflow loops forever.** (1) The agent reports ContextOverflowError (classed `overflow`). (2) nextStep has no overflow case: retryable → the ladder, non-retryable → recover. (3) Each retry/recovery forks the largest source — the overflowed session itself. (4) The copy overflows again on the first call; the tiny probe always succeeds. (5) Repeat indefinitely, each round a full-context request.

## Design notes

- Healthy: the chain consolidation is finished and holds (one writer, named transitions with their rationale), and the ladder decision is pure (engine/ladder.ts) with session.ts as its executor — the shape that made every finding here reproducible in a few lines.
- Worst choice: the recovery machinery's admission and exit tests. Anything not an AgentStartError or an in-session block enters it, and its exit test (a phase-less tiny probe) checks provider availability, not the failure's cause. S13-01 and S13-06 are one shape: a deterministic fault the probe cannot see → unbounded re-dispatch, contradicting P2's "bounded, terminal the person" while P20's wait is ruled only for transient faults.
- Change first: one ruling — "the same failure after a successful probe is not transient": a per-prompt count of recoveries that end in the identical failure face, blocking for the person at 2; plus rethrowing driver exceptions (0037 D2 makes them identifiable) and taking `overflow` out of the ladder.
- Second: the fake agent's prompt resolves at hand-over while opencode's resolves at turn end; every crash-window test therefore pins the CLI-adapter timing (S13-04). Default the fixture to turn-end resolution and pin the claim before the POST.
- session.ts (1046 lines) is ~60% comment; the code itself is navigable, but several comments state invariants the code does not keep (S13-07).
