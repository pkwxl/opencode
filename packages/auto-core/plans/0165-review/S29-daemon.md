(3) It opens `ws://127.0.0.1:4770/runs/<id>/worker?token=oar_…`; the daemon closes the real bridge with "replaced" and adopts the impostor. (4) The person's answer and `/exit` frames now go to the impostor; a forged `settled` is journaled and the person's question disappears from the replay; the real worker reconnects within ≤2 s and the two alternate, the held ask degrading after 5 s (permission → exit 2).

**S29-04 scenario.** (1) Register a plain directory (no `.git`). (2) `POST /projects/<p>/init` → 200 (the CLI's init would have run `git init`). (3) Plan a task and `POST /runs` → the run completes `✓ all tasks complete`, exit 0. (4) Nothing is committed anywhere: no Auto-Stage trail, no SHA baseline audit, no rollback anchor — every later git-reading surface (fork, land, release, status's commit reads) has nothing to read.

**S29-10 scenario.** (1) A client pastes a 200 KB specification into the plan form (or sends a large switch value). (2) `startRun` registers `run-N` as `starting` and journals `opened`, then `Bun.spawn` throws E2BIG; the client gets a 500. (3) Every later `POST /runs`, plan, transfer, close, task-add, init/amend on that project answers 409 "run run-N is starting … retry once the active run reaches a terminal state". (4) `DELETE /runs/run-N` answers 202 "kill requested" and nothing changes; only restarting the daemon clears the project.

## Design notes

- The daemon is carefully reasoned per surface (every refusal names its rule; auth, whitelist and lock arbitration are clean), but its two weak joints are both the **spawn boundary**: one argv token carries everything — the secret (S29-01), unbounded user text (S29-10) — a choice made when the payload was "a handful of options" and never revisited as P3b/P3c grew it.
- The **registry has no failure or end-of-life path**: a run enters before its spawn can fail and nothing ever removes it (S29-10, S29-05, S29-02) — the in-memory registry needs one retire/settle helper used by spawn failure, terminal exit, restored-run expiry and eviction.
- **Shell duplication is drifting by lockstep misses** (0142's banner clause, 0137's phases hint, phasesLine's remedy): the banner, the phase line and the frozen-key hint table belong in the core, read by both shells and status.
- Best choice: the per-run secret + per-frame scope checks on one multiplexed socket. Worst: letting the request carry operator-environment names (S29-06) — the scope tiers' narrowing leaks through the switch layer.
- Change first: S29-10 (wedge) and S29-01 (move the payload off argv — it fixes both), then the registry retire helper.
