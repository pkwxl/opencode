## Design notes

- Health: the recovery ladder itself is the best piece here — one decision, two callers, every rung's why distinct and caller-neutral, and the strict/non-strict split cleanly gated. Its weakness is upstream of it: the *unit's start* is not durable state. The loop re-anchors at HEAD on every resume and re-run (S12-04, S12-05), so two consumers 0145 never weighed — the verification charter's range and the P4 audit — silently narrow. The fix is P6's own answer: derive the unit's start from the trailer-scoped history (0140's bound already exists for fork), never from "HEAD when this process arrived".
- Worst choice: **person marks scanned as whole-document grammars in agent-co-authored documents** (S12-02). `Choice:` is a P2 mark living below a verbatim agent section; the mark readers must be section-scoped and the renderer must neutralize the agent's copies. The executor then trusts the path the agent wrote (S12-12), and its own clean gate refuses the person's honest one-line answer (S12-06) — three defects on one surface, which says the surface was tested with pre-committed fixtures rather than the person's real act.
- Second: **driver-owned state is session-writable and the commit boundary does not look** (S12-01 here, S11-01 for report.md, S12-07's carryover by path pattern). One commit-boundary guard over the unit-state files (done.md, index ticks, verdict files) closes the family.
- What to change first: S12-02 + S12-12 (one wave: mark scoping + path confinement), then S12-01 with S11-01 (the commit-boundary guard), then S12-04/05 (the derived unit start).
- Test-oracle note: blockage-diagnosis.test.ts:233/236 assert `toMatch(/Choice: A/)` anywhere in the document — the same whole-text reading as the defect; the executor suite's seededDoc commits the Choice before executing.
