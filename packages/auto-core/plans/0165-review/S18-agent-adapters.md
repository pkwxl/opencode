### S18-01 failure scenario (S2)

1. The person runs `init` on a project with a root symlink to a reference tree; the target's `opencode.json` carries 0122/0147's `permission.external_directory = {"/**": "deny", "/tmp/**": "allow", "<realpath>/**": "allow"}` beside `permission.edit`'s matching deny — the README's fix table promises this is the project's standing boundary.
2. The person sets `agent: "claude"` (supported: config key, `init --agent claude`, or `OPENCODE_AUTO_AGENT`).
3. Every claude process starts via `contractArgs` → `claudePermissions`, which walks `permission`'s keys against `TOOLS`; `external_directory` is not in `TOOLS` and is skipped — no `--settings` rule is emitted for it under any preset.
4. Under the default preset (`deny` → `--permission-prompts none`): every claude action that would prompt is refused, so reading the reference tree or writing /tmp via file tools is denied per-action — the notes name the tool (`permission denied: Read: …`), never the untranslated key, and nothing at run start taught the loss. Under `--permission auto-allow` (`bypassPermissions`): the deny half is gone entirely if the Claude Code version does not itself gate external reads.
5. The person's declared posture and the run's actual containment silently diverge; the only loud signals point at the tools, not at the boundary.
