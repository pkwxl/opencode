### Failure scenarios (S1/S2)

- **S11-01 (false PASS).** (1) A task's work session writes `docs/T-NNN/report.md` ending `Result: PASS` (an audit deliverable, a self-summary — nothing in whole.md/fix.md forbids it). (2) The driver commits it with the exec stage. (3) The verify session finds a gap, writes `gaps.md` with `### Gap 1` + `Result: FAIL`, writes no report (as the template says). (4) `verifyVerdict` reads report.md first → `pass`. (5) `verifySession` deletes gaps.md, commits (nothing left to commit), returns pass. (6) The task closes `done`; the FAIL exists nowhere in history.
- **S11-02 (unbounded loop).** (1) Verify: 2 gaps (seed). (2) Fix round 1 closes one, breaks something; re-verify: 1 gap → progress, streak 0. (3) Fix round 2; re-verify finds 2 → streak 1. (4) Fix round 3 closes one → 1 < 2 → streak 0. Repeat: the block condition `noProgress >= 2` is never met; the unattended run spends rounds until the verifier happens to PASS or the person interrupts.
- **S11-03 (orphaned lane).** (1) The wrap-up lane gate launches the anchor lane; it hangs silently (a deadlocked test). (2) idleMs elapses → SIGTERM to the wrapper bash → it dies; 10 s later SIGKILL hits the dead pid. (3) The gate reads red (124), runs the set guard (clean), writes receipts, commits the synthesized gap list. (4) The fix session starts while the orphan still holds the build lock and later writes into the tree; those writes ride the fix session's commit.
- **S11-04 (boundary escape).** (1) A session (confined by the 0147 external_directory deny) writes `/home/u/.ssh/id_ed25519` (or `ref/test/run.sh` through a 0122 root symlink) into tmp/test.sh. (2) At idle the driver's test concern calls resolveTestScript: the file exists → `chmod 0755` → executes it as the test with the project cwd. (3) The key is now world-readable / the reference tree's mode changed; nothing is logged beyond a normal test run line.
- **S11-06 (sibling receipt).** (1) The pack declares regression rows `full` and `qemu-full`. (2) `qemu-full` runs green at HEAD; `full` has no green receipt (or its last run was red). (3) At phase close `regressionCovered(full)` globs `*-full.md`, finds `N-qemu-full.md` green with an empty diff → covered. (4) The phase completes without `full` ever running at this tree.
- **S11-08 (WIP erased).** (1) A code-phase session has uncommitted edits and writes tmp/test.sh pointing at test/run.sh, whose preamble is `git checkout -- .` (or `git stash`). (2) runScript snapshots (stash create), runs the script → the session's edits revert to HEAD. (3) The guard's status enumeration sees nothing changed → no violation, no restore. (4) The session reads the test output and continues over files that silently lost its work.

- **0148 reader = writer.** Writer `${task.id} fix ${round}.${ordinal} ${shortTitle(title)}` (wrapup.ts:334); reader prefix `${taskId} fix ${round}.` + parseInt (git.ts:94-106). commitTitle truncates the tail only (TITLE_MAX 100), so the ordinal survives; `T-001 fix 1.` never matches `T-001 fix 10.x`; test-handover suffixes (`… test handover #n`) parse to the same ordinal. No other reader of the ordinals exists (grep).
- **Receipt staleness direction (P12).** Unparsable, headless and red receipts are never carry basis (script.ts:350-358); an unreadable range or a vanished recorded root returns `undefined` → no carry (git.ts:1403-1417); the background slot launches only over a clean tree (regression.ts launchStale `pendingChanges`); an interrupted background run leaves no receipt and preflight clears its copy and marker loudly (recoverRegression). (Exceptions: S11-06, S11-09.)
- **The lane gate's verdict is driver-parsed.** `readLaneVerdict` takes the last `^LANE_RC=(\d+)$` line, a timeout or missing line reads 124/red (script.ts:464-468) — a session cannot turn a driver-run lane green through its log.
- **The fix loop's persistence (0146 D4).** Every wrapup-stage persist carries round/noProgress/gaps (wrapupStage, wrapup.ts:684-686) at the loop entry and before each fix round; the 0142 rewind writes the roundless form (wrapup.ts:387). A kill between the FAIL commit and the pre-round persist re-verifies from scratch (idempotent).
- **The FAIL-side shape gate.** A FAIL without a countable `### Gap N —` heading gets exactly one forked re-prompt, then a hidden-blockage stop naming the file (wrapup.ts:246-271); the same holds for a PASS/none without a well-formed report.
- **knowledge.ts prior-knowledge completion** (closing mark → driver rename → driver commit, ③ backfill, ④ dirty handoff) matches its documented protocol (knowledge.ts:213-263).
- **`sameIssue` breadth** — the suspected over-broad substring match is refuted in the realistic shape (punctuation breaks containment: probe `sameIssue("Which database?", "Which database should …?") = false`).

## Design notes

- Health: the verification core (verdict protocol, shape gates, persistence, receipts' P12 direction) is careful and well-commented, but its **trust boundary is drawn by convention, not code**: report.md, receipts and the test marker are files sessions can write, and the driver reads them as its own (S11-01, S11-04, S11-06's unchecked `Lane:` field; session-forged testhands/regression receipts would be trusted too — seam to S20).
- Best choice: driver-parsed lane verdicts (`LANE_RC` tails) and the snapshot-based side-effect guard — mechanical evidence instead of session claims.
- Worst choice: verdict precedence by file (report.md before gaps.md) instead of by authorship/recency — one ordering rule turned the P3 guarantee into a convention (S11-01).
- Process control is the second weak area: three spawn sites, three different kill semantics, none group-based (S11-03), and full-file log reads (S11-05). One `spawnScript` helper (process group, bounded tail read) would close the family.
- 0146's `2 + N` bound was argued in prose and never pinned; the only progress test is monotone (verify-loop:231). Ruled bounds deserve a property test.
- `knowledge.ts`: the k-phase kb.md still uses the "non-empty = done" criterion that 2026-09-13's rework replaced for prior-kb.md (closing mark); the run-start clean gate likely surfaces a half-written kb.md first (seam to S04) — a sibling inconsistency, not yet a defect.
- Change first: S11-01 (remove report.md/gaps.md at each verification's first dispatch), then S11-08 and S11-03 (one wave in git.ts/script.ts), then S11-02.
