# Executor

Use the registered project and endpoint the operator supplies. Read its URL and bearer token from their local-only JSON file with `url` and `token` fields. Keep the file outside the checkout and the token out of transcripts, logs, and child instructions. Use a stable `channel` for each worker or hub in that project, including across retries. Omit the field to use the token's default channel.

With `CONNECTION` set to the operator's file and `PROJECT` set to the registered name, this shell helper sends a request. Disable shell tracing before using it.

```sh
url=$(jq -er '.url' "$CONNECTION")
project=$(jq -nr --arg name "$PROJECT" '$name | @uri')
executor() {
  jq -er '"Authorization: Bearer " + .token' "$CONNECTION" |
    curl -q --silent --show-error --fail-with-body --header @- \
      --json "$2" "${url%/}/projects/$project/executor/$1"
}
executor ready '{"channel":"worker"}'
executor claim '{"channel":"worker","task":"T-012","kind":"execute"}'
```

Treat HTTP errors as request failures. Show the operator the error if it needs their action. Successful responses carry `protocol: 1` and one payload, `step`, `menu`, or `question`. The `ready` response also carries `build`, the server's version and build commit — read it to detect a stale daemon. Stop and ask the operator to update the client if the protocol or a step kind is unknown; unknown extra fields are additive, not an unknown protocol.

## Solo worker

1. Ask `ready` for `menu.claimable`, or use `claim` for the next available step. Claim a specific unit with its ID as `task` and a kind from the menu. Only a live grant authorizes work.
2. For `execute`, `verify`, `fix`, `formulate`, `distill`, or `audit`, work in the returned `workspace` and follow `prompt`. The coordinator owns staging, commits, and driver state. Never run Git staging or commit operations. The person's direct commits — plain commits carrying none of the coordinator's stage trailers — may appear in the workspace's history between the executor's own shares; the protocol logs and passes them. Never author such a commit yourself — this prohibition is unchanged — and an isolation block over any other unknown commit still means divergence. Leave `.auto/`, the index, task and phase state, configuration, and AGENTS.md to the coordinator. Execute and fix may edit their assigned deliverables within the task's scope and the current task's handoff. Verification may write only the task's report or gap list. Formulation may write only the granted phase's planning documents — the `index` path the grant names, the planned tasks' `todo.md` files, and its coverage map and handoff — never its own input `todo.md`, and never a `done.md`, a tick, or a rename. Distillation may write only the granted phase's `handover` document — the path the grant names, its four protocol sections — never the phase's `todo.md` or `done.md`, the phases index, or another phase's handover: the boundary's completion shapes (the rename, the tick, the transition) stay the person's `transfer` act, and a landed distillation ends the unit — no verification share follows it. The close audit may write only the granted unit's `findings` document — the path the grant names, one section per due row with the row's id in its heading, the document ending with its `Result: PASS` or `Result: FAIL` line — and the unit's handoff: an adjudication judges and documents, it never repairs in-round, so a FAIL is a finding for the person routed at the round's close — no fix ever spins off the audit itself — and the round's close stays the person's `transfer` act. For verification, use a fresh agent context and a different token from the producer of the immediately preceding execute, fix, formulate, or audit share. The `types` block on `ready`'s menu states each work type's restrictions in machine-readable form — the same boundary this paragraph teaches, per-unit scope riding the menu's `touches` and the grant's `workspace`. Provisioning against it — sub-agent templates, sandbox allowlists, or nothing — is the operator's affair; the coordinator's boundary checks are the authority either way.
3. Use the grant's `id` as request field `step` and retain its exact `lease`. Send `heartbeat` with `{"channel":"worker","leases":[{"step":"<id>","lease":"<lease>"}]}` before the deadline in Unix milliseconds. Track the returned deadline. Stop all writes if the lease is gone or expires.
4. If a decision is needed, stop the affected work and send `question` with `text` and the complete `task`, `step`, `lease` tuple. The response's `question.id` identifies the pending item. Raise project-wide questions with `text` alone. Identical raises deduplicate while pending, so reconcile a lost response before raising again after settlement. Refresh the live brief with `brief {"task":"T-012","kind":"execute"}` on the same channel to read answers. If it includes `answerCursor`, send that value as `cursor` on the same brief request and follow each `answers` step's `next` cursor. Use `null` to start from the first answer.
5. End a turn with `report` carrying `step`, `lease`, and `outcome: "ended"` when the brief's work ends, or `outcome: "failed"` when work hits a blocker. A short optional `note` explains what happened. The coordinator judges artifacts and completion. Use `release` with the same pair if giving back work that never began.

A report or release response describes what comes next. Request a fresh claim before starting another work step. For `wait`, sleep `retryAfter` seconds and recheck the menu, the claim, or the current brief as appropriate. A gate wait calls for the person session. Render the remedy and end the session at `blocked` or `phase-boundary`. A `settled` step answers a claim from a token whose share's report was already accepted: its `commit` names where the evidence is booked, this token's work on the unit has ended, and a different token performs the verification — reconcile against the commit and end the session. A `blocked` remedy that names a raised question puts the cause outside the lease's permitted writes: do not retry it — the person holds the item, and its answer returns with a later brief for the task. Show the summary and end at `done`.

If a claim response is lost, check the same channel's `menu.leases` with `ready` before trying another untargeted claim. If the menu shows a lease, claim again with its `kind` and the same channel. A matching `id` and `lease` recovers the held brief. If either value changes because the old lease expired, treat the returned grant as a new attempt and follow its brief. Retry a lost report or release with its original pair and the same report outcome. A successor claim can resume settlement of an already accepted report. A `settled` answer to a same-token claim also reconciles a lost report response: the report landed and its booked commit is named — do not retry it. A stale holder must stop writing and let the new holder continue.

## Hub

Use `ready` to assign an offered task and kind by ID. Start a child with that target and let it claim on its own channel, or claim on a hub-owned channel and pass the leased brief and workspace to a child that cannot make requests. Start work only after the coordinator grants a lease for that task. Use a separate channel for each concurrent worker and keep each worker inside its assigned workspace and scope. A hub that holds the grant handles all requests for that child, including heartbeat and settlement. For self-serving children, have them heartbeat and report or have an authorized caller act on the same token and channel once they stop. Stop an interrupted child before giving back its lease. Report `"failed"` if the child stops after work began, or release if it never began. Leave implementation to the leased worker.

Read each unit's `menu.claimable` kinds and spawn the typed child for the granted kind. Use a hub-held grant when a child's turn can outlast a heartbeat. The resident hub renews on its own token and channel while the child works. Use a self-serving channel when the child can renew throughout its turn. On shutdown, stop the child first, then report failed for work that began or release an unused grant.

The operator decides when to rotate a hub session. For planned rotation, end the session with its live grants riding to their deadlines. The successor's first duty in an inherited workspace is to stop any orphaned child. Recover through `menu.leases` on the same token and channel before dispatching another writer.

Keep project loops and leases separate. Use `GET /projects` with `read` to list registered projects. Where the operator enabled open creation, `POST /projects` with `projects` accepts `root`, `name`, and optional `config` for a new directory under a declared root. Retry creation with the same token and unchanged body.
