# Executor

Use the registered project and endpoint the operator supplies. Read its URL and bearer token from their local-only JSON file with `url` and `token` fields. Keep the file outside the checkout and the token out of transcripts, logs, and child instructions. Use a stable `channel` for each worker or hub in that project, including across retries. Omit the field to use the token's default channel.

The claimant's host and model are its own affair: any coding-agent session may claim a grant — nothing in the protocol presumes, provisions, or names a host.

With `CONNECTION` set to the operator's file and `PROJECT` set to the registered name, this shell helper sends a request. Disable shell tracing before using it.

```sh
url=$(jq -er '.url' "$CONNECTION")
project=$(jq -nr --arg name "$PROJECT" '$name | @uri')
executor() {
  jq -er '"Authorization: Bearer " + .token' "$CONNECTION" |
    curl -q --silent --show-error --fail-with-body --header @- \
      --json "$2" "${url%/}/projects/$project/executor/$1"
}
executor ready '{"channel":"worker"}'
executor claim '{"channel":"worker","task":"T-012","kind":"execute"}'
```

Treat HTTP errors as request failures. Show the operator the error if it needs their action. Successful responses carry `protocol: 0.1` — the preview wire — and one payload, `step` or `menu`. The `ready` response also carries `build`, the server's version and build commit — read it to detect a stale daemon. Stop and ask the operator to update the client if the protocol or a step kind is unknown; unknown extra fields are additive, not an unknown protocol.

## Solo worker

1. Ask `ready` for `menu.claimable`, or use `claim` for the next available step. Claim a specific unit with its ID as `task` and a kind from the menu. Start new work only under a live grant.
2. For `execute`, `verify`, `fix`, `formulate`, `synthesize`, `distill`, or `audit`, work in the returned `workspace` and follow `prompt`. An execute grant over a unit with a landed share carries `landed: { id, commit }` — the prior share's id and its landing commit; the takeover or continuation holder reads its unit's already-landed state from the grant, not the tree, and the key is absent on a fresh unit. The coordinator owns staging, commits, and driver state. Never run Git staging or commit operations. The person's direct commits — plain commits carrying none of the coordinator's stage trailers — may appear in the workspace's history between the executor's own shares; the protocol logs and passes them. Never author such a commit yourself — this prohibition is unchanged — and an isolation block over any other unknown commit still means divergence. Leave `.auto/`, the index, task and phase state, configuration, and AGENTS.md to the coordinator. Execute and fix may edit their assigned deliverables within the task's scope and the current task's handoff. Verification may write only the task's report or gap list — the settled artifact is that path's sole write, closing with its machine-read verdict line before the final `<!-- auto: eof -->` terminator: a PASS report carries `Result: PASS` (the last `Result:` line governs); a FAIL gap list is written alone — the report absent — carrying `Result: FAIL` and one `### Gap` heading per countable gap. Formulation may write only the granted phase's planning documents — the `index` path the grant names, the planned tasks' `todo.md` files, and its coverage map and handoff — never its own input `todo.md`, and never a `done.md`, a tick, or a rename. Synthesis may write only the granted unit's own `todo.md` path — and what it writes there is its reply, exactly the shape the prompt prescribes (the `<<<SOURCES-BRIEF` / `<<<LEDGER` blocks and the closing `Rationale:` line): the driver parses the reply, validates it mechanically (every quote must locate in its named source), composes the real synthesized todo and lands the construction itself — so rewrite the file wholesale with the reply and nothing else. Include a literal dash and space at the start of each ledger row. Validation consumes the submitted reply and restores the input todo. If validation refuses it, use the findings to compose the complete corrected reply at that path before retrying the original report. A landed synthesis ends the unit's claim — no verification share follows it; the formulation session continues over the synthesized todo. Distillation may write only the granted phase's `handover` document — the path the grant names, its four protocol sections — never the phase's `todo.md` or `done.md`, the phases index, or another phase's handover: the boundary's completion shapes (the rename, the tick, the transition) stay the person's `transfer` act, and a landed distillation ends the unit — no verification share follows it. The close audit may write only the granted unit's `findings` document — the path the grant names, one section per due row with the row's id in its heading, the document ending with its `Result: PASS` or `Result: FAIL` line — and the unit's handoff: an adjudication judges and documents, it never repairs in-round, so a FAIL is a finding for the person routed at the round's close — no fix ever spins off the audit itself — and the round's close stays the person's `transfer` act. For verification, use a fresh agent context and a different token from the producer of the immediately preceding execute, fix, formulate, or audit share. The `types` block on `ready`'s menu states each work type's restrictions in machine-readable form — the same boundary this paragraph teaches, per-unit scope riding the menu's `touches` and the grant's `workspace`. Provisioning against it — sub-agent templates, sandbox allowlists, or nothing — is the operator's affair; the coordinator's boundary checks are the authority either way.
3. Use the grant's `id` as request field `step` and retain its exact `lease`. Send `heartbeat` with `{"channel":"worker","leases":[{"step":"<id>","lease":"<lease>"}]}` before the deadline in Unix milliseconds. Track the returned deadline. Stop all writes if the lease is gone or expires.
4. Refresh the live brief with `brief {"task":"T-012","kind":"execute"}` on the same channel — a held lease is re-answered with the same grant for its holder.
5. End a turn with `report` carrying `step`, `lease`, and `outcome: "ended"` when the brief's work ends, or `outcome: "failed"` when work hits a blocker. For a graceful stop during formulation before writing planning output, write the unit's handoff with `Status: continue` and the steps to resume, then report `ended`. This continuation must change only the handoff. If you changed planning documents, settlement checks the full formulation output. A short optional `note` explains what happened. The coordinator judges artifacts and completion. Use `release` with the same pair if giving back work that never began.

A report or release response describes what comes next. Request a fresh claim before starting another work step. Every `wait` and `blocked` answer carries an `actor` field naming the role whose move clears it (plans/0308) — the protocol's rule that a role playing properly always has a named move. For `actor: "workflow"`, sleep `retryAfter` seconds (stamped only on these waits) and recheck the menu, the claim, or the current brief as appropriate, or take other claimable work — no one must act, and the menu's `waiting` rows (parked units naming their blocker) are this class read as data. For `actor: "executor"`, the move is yours alone: correct your own artifact within the granted write surface and retry the same report, release the lease, or park the unit. For `actor: "person"` or `actor: "operator"`, render the remedy and end the session — the move belongs to the named role, never you, and a `wait` carrying no `retryAfter` is one of these. End the session at `phase-boundary` the same way. A `settled` step answers a claim from a token whose share's report was already accepted: its `commit` names where the evidence is booked, this token's work on the unit has ended, and a different token performs the verification — reconcile against the commit and end the session. A `blocked` remedy that names a person-necessary cause puts it outside the lease's permitted writes: do not retry it — there is no ask channel (plans/0282); resolve what you can yourself, record your decision in your artifact, and end the session. A gate wait calls for the person's own act (the document edit or the deterministic clarify op), never yours. Show the summary and end at `done`.

If a claim response is lost, check the same channel's `menu.leases` with `ready` before trying another untargeted claim. If the menu shows a lease, claim again with its `kind` and the same channel. A matching `id` and `lease` recovers the held brief. If either value changes because the old lease expired, treat the returned grant as a new attempt and follow its brief. Retry a lost report or release with its original pair and the same report outcome. If a booked report still lacks a receipt and you lost its pair, use `brief` with the original token, channel, task and kind. Use its original `id` and `lease` to retry the report after addressing the settlement finding. The pair appears in the channel’s `menu.leases` only while it is live. Use a booked pair for settlement recovery. A successor claim can resume settlement of an already accepted report. A `settled` answer to a same-token claim also reconciles a lost report response: the report landed and its booked commit is named — do not retry it. A stale holder must stop writing and let the new holder continue.

## Hub

Use `ready` to assign an offered task and kind by ID. Start a child with that target and let it claim on its own channel, or claim on a hub-owned channel and pass the leased brief and workspace to a child that cannot make requests. Start work only after the coordinator grants a lease for that task. Use a separate channel for each concurrent worker and keep each worker inside its assigned workspace and scope. A hub that holds the grant handles all requests for that child, including heartbeat and settlement. For self-serving children, have them heartbeat and report or have an authorized caller act on the same token and channel once they stop. Stop an interrupted child before giving back its lease. Report `"failed"` if the child stops after work began, or release if it never began. Leave implementation to the leased worker.

Read each unit's `menu.claimable` kinds and spawn the typed child for the granted kind. Use a hub-held grant when a child's turn can outlast a heartbeat. The resident hub renews on its own token and channel while the child works. Use a self-serving channel when the child can renew throughout its turn. On shutdown, stop the child first, then report failed for work that began or release an unused grant.

The operator decides when to rotate a hub session. For planned rotation, end the session with its live grants riding to their deadlines. The successor's first duty in an inherited workspace is to stop any orphaned child. Recover through `menu.leases` on the same token and channel before dispatching another writer.

Keep project loops and leases separate. Use `GET /projects` with `read` to list registered projects. `POST /projects` with `projects` takes `{"directory": "<absolute path>"}` — the request names the directory to create, its parent the anchor (an operator-owned directory without group or public write), the basename the project name, an optional `name` field overriding it, an optional `config` object the init the staged creation runs with. Retry creation with the same token and unchanged body.
